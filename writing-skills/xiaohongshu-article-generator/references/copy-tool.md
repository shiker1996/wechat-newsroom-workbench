# 工具图文配套文案规则

只负责已锁定工具故事板的对外文案，不重新设计页序、页面职责或内容块。

## 输出形态

纯文本，直接可发布：不使用 Markdown 或 HTML 标记（标题、加粗、列表符号、链接语法一律禁止），结构只用分行、空行和数字编号表达；公众号与小红书图文均不渲染标记文案。

## 表达目标

- 用一句话说明工具解决的具体问题并点明读者可获得的明确收益，再解释已核验能力和开始方式。
- 对程序员说人话，但保留必要术语。
- 区分项目自述、第三方评价和作者判断。
- 没有真实体验时不用“我用了”“亲测”“踩坑”。
- 数字、免费、开源、性能、价格和节省时间必须有事实基座支持。

## 渠道

- 公众号：信息密度优先，短段落；末尾给 6–8 个准确话题标签。
- 小红书：可以使用克制的 emoji 和口语表达，末尾给 6–8 个准确话题标签。

## 事实边界

- Star、版本等实时数字必须保留采集时间语境。
- 开源协议、安装命令、权限和网络要求只采用已核验材料。
- 项目处于 alpha、beta 或实验阶段时必须明确说明。
- 未实际运行时保留“基于项目文档整理，未实际运行”。
