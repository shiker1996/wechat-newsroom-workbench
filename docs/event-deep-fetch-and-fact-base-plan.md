# 事件精选深抓与事实基座升级：验证与推进计划

> 创建：2026-07-25。承接 `optional-feature-todos.md` 待办 7 的剩余项（P2 事件内精选深抓）。
> 前置已完成：P0 事件卡、P1 启发式质量评分（`lib/source-quality.mjs`）、P2 抓取路由（`lib/source-fetcher.mjs`，阈值见 `config.local.json` 的 `sourceFetch` 段）。

## 背景与判断

抓取路由已保证"每条来源用最低的代价拿到内容"（RSS 免抓 → GitHub API → Python 本地 → Firecrawl 计费升级），但路由只解决"拿得到"，不解决"用得好"。

剩余工作的核心不是多抓网页，而是：**深抓产出的全文需要一条"逐源提取事实 → 合并去重 → 标注确认/主张/分歧 → 写入事实基座"的链路才有意义**。没有这条链路，深抓的全文只会堆在 `data/source-cache/`，成稿与质量门禁消费的字段不会因此变准。

为避免"先投入复杂基础设施却没有改善总结质量"（待办 7 启动条件的警告），先做小范围验证，再决定是否铺开。

## 第一步：验证事项（小范围实验）

目标：用最小成本回答一个问题——**事件级事实提取是否明显优于现在的事件卡 + 编辑室整理**。

- [ ] 选取 1 个真实事件：来源 ≥5 条、来源间存在信息增量（推荐从最近批次的热点全景里挑，如多媒体报道的科技事件）。
- [ ] 对该事件手动触发深抓：取 2~3 个代表来源（优先 `evidence_level` 为 full-text 的， Firecrawl 消耗 ≤3 次额度）。
- [ ] 用模型对每个来源做事件级事实提取，输出结构化结果：
  - 事实陈述 + 来源 URL + 证据等级（full-text / partial / rss-summary）
  - 分类：多源交叉确认 / 单一来源主张 / 与其他来源分歧
- [ ] 人工对比三份产物：
  1. 现有事件卡（标题 + 摘要 + 模型研判）
  2. 深抓提取的事件级事实集
  3. 同选题实际成稿时编辑室整理出的事实基座
- [ ] 记录对比结论：新事实数量、纠正的错误、分歧发现、token 与抓取成本。

### 验证通过标准（满足两条即进入第二步）

- 提取出事件卡中没有、且对成稿有用的新事实 ≥3 条；或纠正事件卡错误 ≥1 处。
- 分歧识别至少 1 处是人工此前未注意到的。
- 单事件成本可接受：Firecrawl ≤3 次、模型调用 ≤5 次、耗时 ≤2 分钟。

### 验证不通过的处理

- 若深抓事实与事件卡质量相当：维持现状，事件卡 + 编辑室整理继续承担事实整理，本事项关闭并在待办 7 标注结论。

## 第二步：事实基座升级（验证通过后实施）

- 事实基座数据结构扩展：事实条目增加 `source_url`、`evidence_level`、`fact_kind`（confirmed / claim / dispute）字段；与现有 `confirmed_facts` / `open_questions` 衔接。
- 事件级事实提取管道：深抓 → 逐源提取 → 跨源合并去重 → 分歧标注；分歧可回传抓取层触发追加来源抓取（闭环）。
- 编辑室展示：事实基座按"已确认 / 媒体主张 / 分歧"分组展示，分歧项附各来源原文位置。
- 成稿与门禁衔接：质量门禁按证据等级校验引用（full-text 事实可直接引用，claim 级需标注"据 XX 报道"）。

## 第三步：精选深抓自动化（事实基座落地后实施）

- 事件聚类后自动挑选 2~3 个代表来源：优先证据等级高、来源类型互补（官方公告 + 媒体 + 社区）、内容增量大的。
- 触发时机：候选进入选题池时深抓（而非热点全景阶段全量深抓），控制额度消耗。
- 预算约束：单事件 Firecrawl ≤3 次；批次级预算可配（建议加入 `sourceFetch` 配置段）。

## 验收标准（整体）

- 选题池候选的事实基座包含来源可追溯、分证据等级的事件级事实。
- 同一事件的多来源增量和分歧在编辑室可查看。
- 300 条级别批次的 Firecrawl 消耗可控（仅精选来源 + 质量不足升级）。
- 成稿质量门禁不再出现"事实在基座中标记为 unverified 但实际有全文来源"类的误报。

## 成本与风险

- 模型成本：逐源事实提取是新增模型调用点，验证阶段先人工触发，自动化阶段需限速。
- Firecrawl 额度：每月 1000 次，深抓只走精选来源，预计单事件 ≤3 次，日常批次远低于限额。
- 风险：事实提取的错误合并（把分歧误判为确认）——通过分歧保守标注（拿不准就标 claim）和成稿门禁兜底。
