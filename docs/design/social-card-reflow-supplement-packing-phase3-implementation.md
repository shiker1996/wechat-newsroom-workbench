# Social 图文补充装箱与拆页联合评分：阶段 3 实施记录

## 目标

阶段 2 已能为单个补充组件选择压缩或字体放大变体，但逐页贪心仍可能出现：某页补充块看似可放，另一页续页因此继续偏空，或者多个补充块组合后把页面推过浏览器门禁。阶段 3 增加页面组级联合评分。

## 实施内容

新增 `selectBestSocialCardJointPackingOperations`，对已通过来源、槽位和单页容量守卫的候选操作做有界组合评估：

1. 计算“不增加补充块”的基线分数；
2. 枚举最多 4 个候选操作的有限组合；
3. 模拟写入各目标页，重新计算模板容量和利用率；
4. 对溢出、超过安全利用率、低于角色目标利用率分别计分；
5. 只接受整体分数严格改善的组合，否则保持原计划。

角色目标暂采用：普通内容页 `72%`、步骤页 `68%`、续页 `62%`。这些目标只用于候选排序，不替代浏览器硬门禁。

## 链路接入

联合评分已接入：

- 原始续页的确定性补充装箱；
- 内容计划调整后的拆页续页再装箱；
- 无有效 AI 计划时的确定性事实补充兜底。

评分结果随 `reflowHistory` 或 `contentPlanAdjustmentHistory` 写入 `jointPacking`，包含基线分数、最终分数和逐页诊断，便于定位“候选没选”还是“容量不允许”。

## 边界

- 不改变 AI 的 `add_component` 外部契约；
- 不跨页面移动核心故事板块；
- 不绕过 `canFitFactBlock` 和浏览器布局审计；
- 不为了提高分数删除事实、列表条目、代码或来源引用；
- 组合搜索有界，避免因事实候选数量增加造成指数级耗时。

## 测试

新增回归用例验证：一个会使页面溢出的长候选与一个安全候选同时存在时，联合评分会跳过前者并选择整体更优的方案。阶段 3 完成后继续运行 `node --test test/social-card-*.test.mjs`。
