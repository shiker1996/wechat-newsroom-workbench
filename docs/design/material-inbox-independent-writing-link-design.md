# 素材入箱与自主写作链路优化设计

> 状态：设计评审中，尚未实施
>
> 日期：2026-09-04
>
> 目标：让素材从“被保存的原始记录”转化为“可确认的文章或图文命题”，同时保持现有文章生成、审稿、排版和图文生产能力不变。

## 1. 背景与核心判断

当前系统已经具备素材入箱、素材评估、自主写作和自定义图文能力，但这些能力还没有形成完整的编辑链路。

核心判断：

> 当前问题不是“素材太少”，而是素材进入生产流程时缺少一层“主线与观点提炼”。系统把原始素材当成了写作要点，导致文章可能事实完整，却没有明确冲突、作者判断和读者可讨论的问题。

当前链路的主要缺口有三处：

1. 素材入箱页面没有提供编辑入口。后端已经支持 `PATCH /api/writing-materials/:id`，但前端素材卡只显示“分析与推荐”和“用于自主写作”等动作。
2. 素材进入自主写作时，服务端会把原始文本按句子切分为 `【素材】` 要点，前端还会用素材标题初始化主题。这是事实搬运，不是主线提炼。
3. 自定义图文表单目前主要接受 `materialUrls`，没有把素材箱中的 `selectedMaterialIds` 作为一等输入，因此入箱素材无法自然进入自定义图文。

## 2. 目标与非目标

### 2.1 目标

1. 素材入箱后可以继续编辑、补充和修正，不破坏原始来源追溯。
2. 素材可以进入自主写作和自定义图文两个生产方向。
3. 在开始生成前，系统先帮助作者形成可确认的文章主线、核心观点和讨论问题。
4. 文章和图文共用同一份素材简报，避免两个流程分别理解同一批素材。
5. 现有文章事实门禁、标题、审稿、SEO、排版和图文故事板能力继续复用，不另起一套生产管线。
6. 区分“系统建议”和“作者确认”，不把模型生成的观点伪装成作者真实经历或最终立场。

### 2.2 非目标

- 不重写现有自主写作、文章生成、排版和图文生成管线。
- 不把所有素材自动生成文章；素材仍需要作者确认主线和事实边界。
- 不把素材评估分数直接当成文章传播度或讨论度保证。
- 不把外部资料、模型建议或本地文件自动标记为作者亲身体验。
- 不取消外部 URL 素材入口；它仍作为自定义图文的补充来源。

## 3. 新的概念分层

素材链路需要把以下对象分开保存：

```text
原始素材
  ↓ 整理
素材卡
  ↓ 系统分析
素材评估
  ↓ 模型提炼
素材简报草案
  ↓ 作者选择、编辑、确认
锁定命题
  ↓ 选择生产方向
文章事实基座 / 图文事实表
```

### 3.1 原始素材

回答“我记录了什么”。保留来源、时间、原文、标签和隐私边界。原文允许作者修改，但需要保留更新时间和来源信息；如果未来需要版本追溯，再增加修订记录，不在第一阶段引入复杂版本管理。

### 3.2 素材评估

回答“这条素材是否值得继续加工”。继续使用现有的账号切合度、完整度、话题潜力、深挖方向和历史表现等确定性评估。评估是推荐和排序信号，不是文章观点。

### 3.3 素材简报

回答“这条素材可以从什么角度写”。这是本次改造新增的核心中间层，内容可由模型生成草案，再由作者选择和修改。

### 3.4 锁定命题

回答“这次具体要写什么”。至少包含一个确认后的主线、核心观点或问题、目标读者和证据范围。只有锁定命题后，才进入文章或图文生产。

## 4. 总体流程

```text
快速记录 / 外部资料 / 项目复盘 / 生活观察
                    ↓
                 素材入箱
                    ↓
          编辑素材卡：标题、正文、标签、来源
                    ↓
              分析与提炼主线
                    ↓
       事实摘要 / 冲突 / 意义 / 观点候选 / 讨论问题
                    ↓
               作者确认或修改
                    ↓
       ┌────────────┼────────────┐
       ↓            ↓            ↓
    自主写作      自定义图文     写作计划
       ↓            ↓            ↓
  现有文章管线   现有图文管线   现有日历管线
```

流程中“分析与提炼主线”是一个显式步骤，不应在用户点击“用于自主写作”后静默完成。用户可以直接使用已经确认的简报，也可以跳过提炼进入原有表单，但跳过时应明确提示“当前只有原始素材，文章主线尚未确认”。

## 5. 素材入箱页面设计

### 5.1 素材卡信息层级

素材卡默认只展示影响决策的信息：

```text
来源类型 · 记录时间 · 状态
素材标题
一句话摘要或原文摘录
标签       账号切合度 / 完整度 / 话题潜力
主线状态：未提炼 / 有候选 / 已锁定

[编辑] [分析与提炼] [用于自主写作] [用于自定义图文]
```

原始全文、评估理由、证据详情和历史推荐默认折叠，避免素材列表再次变成高密度信息墙。

### 5.2 编辑入口

点击“编辑”打开右侧抽屉，不跳转页面。抽屉分为两层：

#### 基础整理

- 素材标题；
- 来源类型；
- 发生/记录时间；
- 原始内容；
- 标签；
- 推荐栏目；
- 素材状态；
- 隐私或公开范围。

#### 继续加工

- 发生了什么；
- 为什么值得记录；
- 结果、失败或反转；
- 证据和来源链接；
- 下一步想验证什么。

第一阶段可以先开放已有接口支持的基础字段；继续加工字段应在简报结构确定后一起落地，避免同一字段在素材卡、文章表单和图文表单中重复维护。

### 5.3 状态建议

```text
待整理 → 已整理 → 已提炼 → 已锁定 → 已用于文章/图文
   └──────────────────────→ 暂不使用 / 归档
```

状态只表示编辑阶段，不等同于文章生成状态。素材被用于文章后仍可以保留并再次用于系列内容，但默认需要新建或复制一份锁定命题，避免修改旧命题影响已生成内容。

## 6. “分析与提炼主线”工作区

### 6.1 输出结构

模型只生成候选草案，服务端负责结构校验和来源绑定。建议输出：

```json
{
  "material_id": 123,
  "fact_summary": [
    {"text": "已确认事实", "source": "material", "confidence": "confirmed"}
  ],
  "context": "这件事所处的背景",
  "tension": "冲突、反差或未解决问题",
  "why_it_matters": "对目标读者的影响",
  "mainline_candidates": [
    {
      "id": "mainline-1",
      "title": "主线名称",
      "question": "围绕什么问题展开",
      "thesis": "候选核心观点",
      "argument": ["论据方向"],
      "counter_argument": "可能的反方或限制",
      "evidence_refs": ["material-fact-1"]
    }
  ],
  "discussion_question": "读者可能争论的问题",
  "missing_evidence": ["仍需补充或核验的内容"],
  "recommended_formats": ["article-experience", "social-opinion"]
}
```

### 6.2 页面呈现

工作区采用“左侧证据、右侧命题”的双栏结构：

- 左侧：原始素材、证据片段、来源和待核验项；
- 右侧：事实摘要、冲突、主线候选、核心观点、讨论问题；
- 顶部：当前素材状态、账号/栏目匹配、推荐生产方向；
- 底部：`保存草案`、`确认此主线`、`返回素材箱`。

主线候选使用单选卡片，作者可以：

- 选择一个候选；
- 修改主线标题；
- 修改核心观点；
- 修改讨论问题；
- 删除不成立的论据；
- 标记“缺证据，暂不生成”。

### 6.3 讨论度门槛

系统不承诺“生成后一定有讨论度”，但在生成前检查是否具备讨论基础：

1. 是否有明确问题或冲突，而不只是事件摘要；
2. 是否有可被读者同意或反对的判断；
3. 是否有至少一条素材证据支撑该判断；
4. 是否说明适用边界、反例或不确定性；
5. 是否明确目标读者为什么关心。

不满足时不阻止保存素材简报，但将状态标记为“待补主线”或“待补证据”，默认不直接进入生成。

## 7. 自主写作链路调整

### 7.1 进入方式

素材卡的“用于自主写作”有两种情况：

#### 已有锁定命题

直接进入自主写作页面，并将锁定命题作为事实表初始值：

- `topic`：确认后的文章主线；
- `audience`：简报中的目标读者；
- `thesis`：确认后的核心观点；
- `points`：论据和证据引用；
- `selectedMaterialIds`：素材来源 ID。

#### 只有原始素材或分析草案

先打开“主线确认”步骤，再进入自主写作。允许作者跳过，但页面必须显示未确认提示，不应把素材标题静默当作文章主题。

### 7.2 自主写作页面的信息分层

现有表单可以继续保留，但分为三层：

1. **已锁定命题**：主线、核心观点、目标读者、讨论问题；
2. **文章事实表**：论据、步骤、作者体验、限制和证据；
3. **来源依据**：原始素材全文和来源链接，默认折叠。

当前“把原文切成 `【素材】` 要点”的逻辑不能继续作为主线生成方式。原始素材可以作为事实补充传给现有事实基座，但必须由简报中的论据和证据映射承担文章结构。

### 7.3 经验文与教程的边界

- 心得经验：重点消费真实经历、取舍、失败、判断和反思；必须有作者确认的观点或体验。
- 使用教程：重点消费可复现环境、步骤、结果和限制；素材中的观点只能作为背景，不能替代可执行步骤。
- 如果素材只有新闻摘录或外部资料，不应自动进入“心得经验”的作者体验字段。

现有文章生成和真实性门禁继续执行；本方案只改变进入事实基座前的输入组织方式。

## 8. 自定义图文链路调整

### 8.1 输入统一

自定义图文同时支持两类素材：

```text
素材箱内部素材：selectedMaterialIds
外部来源链接：materialUrls
```

两者都进入统一的来源事实表，但来源等级必须保留：

- 素材箱中的作者记录：根据作者确认状态标记为作者素材或待确认素材；
- 外部链接：标记为外部素材；
- 模型生成的包装建议：只能标记为建议，不能作为事实。

### 8.2 进入方式

素材卡点击“用于自定义图文”后：

1. 打开自定义图文工作区；
2. 自动带入已锁定命题和素材 ID；
3. 根据内容类型选择教程、清单或观点图文；
4. 将简报中的证据转换为图文要点草案；
5. 作者确认页数、渠道、要点和来源后，继续使用现有故事板与生成流程。

如果当前简报适合文章但不适合图文，页面给出推荐理由，但不强制阻断；最终路线由作者决定，现有图文门禁继续负责事实完整度和来源等级校验。

### 8.3 与文章的关系

文章和图文可以来自同一素材，但不是同一份输出：

- 文章强调主线、论证、观点和上下文；
- 图文强调信息密度、分页节奏、收藏价值和视觉表达。

二者共享素材简报和来源证据，但各自生成适合本渠道的内容结构。

## 9. 数据与接口设计

### 9.1 不建议复用 `assessment` 保存主线

现有 `assessment` 主要保存评分、推荐栏目、深挖方向和标题方向。它是系统评估，不是作者确认的创作资产。建议新增独立的素材简报实体，避免以下混淆：

- 系统推荐被误认为作者观点；
- 重新评估素材时覆盖已确认命题；
- 文章和图文无法记录各自使用的命题版本。

### 9.2 推荐实体

```text
WritingMaterialBrief
├── id
├── materialIds
├── status                 # draft / confirmed / superseded
├── factSummary
├── context
├── tension
├── whyItMatters
├── mainlineCandidates
├── selectedMainlineId
├── confirmedTopic
├── confirmedThesis
├── discussionQuestion
├── audience
├── evidenceRefs
├── missingEvidence
├── recommendedFormats
├── confirmedBy
├── confirmedAt
├── createdAt
└── updatedAt
```

如果希望先做最小版本，可以暂时将草案保存在素材的扩展 JSON 中，但正式版本仍建议使用独立实体，因为一条素材可能产生多个不同的文章或图文命题。

### 9.3 推荐接口

```text
GET    /api/writing-materials/:id
PATCH  /api/writing-materials/:id
POST   /api/writing-materials/:id/assessment

POST   /api/writing-material-briefs
GET    /api/writing-material-briefs/:id
PATCH  /api/writing-material-briefs/:id
POST   /api/writing-material-briefs/:id/generate
POST   /api/writing-material-briefs/:id/confirm
```

其中现有素材接口可以直接用于第一阶段的编辑能力。简报接口新增后，文章和图文创建接口统一接收：

```json
{
  "selectedMaterialIds": [123],
  "briefId": 456,
  "topic": "作者确认后的主线",
  "thesis": "作者确认后的观点"
}
```

服务端仍需重新读取素材和简报，不能信任前端直接提交的完整事实内容；前端提交的是选择关系和作者确认字段，来源事实由服务端统一装配。

## 10. 与现有能力的兼容边界

本方案只调整“素材如何进入生产输入”，不改已有生产能力：

```text
素材入箱与简报层       ← 本方案新增/调整
          ↓
现有文章事实基座与生成层 ← 保留
          ↓
现有标题、审稿、SEO、排版 ← 保留

素材简报与来源事实表     ← 本方案新增/调整
          ↓
现有图文事实表与故事板   ← 保留
          ↓
现有图文生成、重排、渲染 ← 保留
```

不通过全局 prompt 注入改变所有 Agent 的行为；如果需要模型提炼主线，应作为素材链路自己的独立能力调用，并将结果保存为简报草案。文章 Agent 和图文 Agent 只消费已确认的结构化输入。

## 11. 分阶段实施建议

### Phase 1：补齐素材编辑和路由入口

- 素材卡增加编辑抽屉；
- 调用现有 `PATCH /api/writing-materials/:id`；
- 素材卡增加“用于自定义图文”；
- 自定义图文请求增加 `selectedMaterialIds`；
- 继续保留 `materialUrls`；
- 不改变文章和图文生成 prompt。

### Phase 2：建立素材简报

- 增加素材简报实体和接口；
- 增加“分析与提炼主线”工作区；
- 输出事实摘要、冲突、主线候选、观点候选、讨论问题和待补证据；
- 支持作者选择、修改和确认；
- 素材卡显示主线状态。

### Phase 3：接入自主写作与自定义图文

- 自主写作优先消费已确认简报；
- 自定义图文复用同一简报；
- 原始素材默认折叠，仅作为可追溯来源；
- 生成前增加“主线/观点/证据”完整性检查；
- 保留跳过简报的兼容入口，但明确标记为“未提炼素材”。

### Phase 4：计划与复盘承接

- 从锁定命题创建现有写作计划；
- 将使用过的简报、文章、图文和发布结果关联；
- 后续用实际阅读、分享和转粉数据反哺“主线类型”和“包装形式”建议；
- 不把一次表现直接解释为主线因果结论。

## 12. 验收标准

1. 素材入箱后可以编辑标题、正文、标签和状态，刷新页面后修改仍存在。
2. 同一条素材可以分别进入自主写作和自定义图文。
3. 自主写作不再默认把素材标题当作文章主题，也不再只靠原文切句生成文章要点。
4. 生成前可以看到事实摘要、冲突、主线候选、核心观点和讨论问题。
5. 作者可以修改模型建议，并明确确认最终主线和观点。
6. 每个文章或图文项目都能追溯到素材 ID、简报 ID 和证据引用。
7. 外部 URL 素材和素材箱内部素材可以同时使用，来源等级不混淆。
8. 未确认作者体验不会自动进入作者经历字段。
9. 现有文章生成、真实性门禁、审稿、SEO、排版、故事板和渲染能力的行为保持不变。
10. 没有主线但只有原始素材时，系统允许保存和继续整理，但给出“未提炼”状态，不静默制造一个看似确定的观点。

## 13. 待评审决策

1. 是否允许“只有原始素材”直接进入旧版自主写作表单，还是统一先经过主线确认？
2. 素材简报是否采用独立表，还是先放入素材扩展 JSON 做 MVP？
3. 一条素材是否允许同时锁定多个命题，例如一条文章主线和一条图文主线？本方案建议允许，但每个生产项目只绑定一个锁定命题。
4. “讨论度门槛”是只做提示，还是在未满足时阻止生成？本方案建议第一阶段提示，第二阶段再根据实际误报率决定是否阻断。
5. 素材原文编辑是否需要第一阶段就保留版本记录？本方案建议先保留更新时间和来源，不在 MVP 引入完整版本管理。
