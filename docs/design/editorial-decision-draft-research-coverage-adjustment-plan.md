# 决策底稿研判采用与文章贴合度改造方案

状态：已实施，待用户重跑编辑室与成稿链验证
日期：2026-09-03
关联方案：[从讨论研判到高讨论文章的选题链改造方案](./discussion-oriented-topic-research-adjustment-plan.md)

## 1. 改造背景

当前研判已经能够产出：

- 事件内反常、利益冲突和可发散方向；
- 事件间前后、回应、对比、趋势和反例关系；
- 基于上述内容形成的候选选题和研判报告。

但编辑室的“决策底稿”只有一个自由文本字段 `research_basis` 来记录研判主线。它同时承担“选择哪些研判点”和“概括文章主线”两项职责，造成以下问题：

1. 作者选中的具体研判拓展点没有被结构化保存；
2. 文章写作阶段只收到一句主线，无法知道哪些反常、冲突、对比或反例需要展开；
3. 作者明确舍弃的研判方向没有稳定记录，后续模型可能重新写回；
4. 事实门禁能够检查事实来源，却不能检查研判观点是否真正进入文章。

因此，本方案只调整“研判结果 → 决策底稿 → 成稿”的承接，不改变阶段 0～3 的研判流程、阶段 3 候选生成逻辑和评分公式。

## 2. 改造目标

让决策底稿明确回答四个问题：

1. 文章采用了哪些事件内和事件间研判点？
2. 每个研判点由哪些事实和证据支撑？
3. 作者准备如何解释这些研判点，最终站在哪个判断上？
4. 成稿是否真正兑现了作者选中的研判拓展点？

目标不是要求文章复述整份研判报告，也不是强制每篇文章同时使用事件内和事件间关系，而是让作者明确选择过的内容不会在写作链路中丢失。

## 3. 决策底稿表单调整

### 3.1 新增“研判采用清单”

在决策底稿中增加 `adopted_research_points`。页面以研判卡形式展示，不要求作者手填内部 ID。首次进入编辑室时不自动选择任何研判点；先由编辑室 Agent 通过对话帮助作者明确观点、写作角度和文章命题。角度与命题明确后，Agent 直接根据当前命题选择 1～3 条最适合展开的研判点，通过 `editorial.research.select` 业务工具写入采用清单，不再等待作者重复确认；作者仍可在页面手动调整。

研判卡分为两组：

#### 事件内研判

- 反常点：预期、承诺、过去做法与当前结果的落差；
- 利益冲突：收益、成本、责任和解释权如何在参与方之间分配；
- 可发散方向：行业基线、影响路径、后续验证信号和替代解释。

#### 事件间研判

- 前后关系；
- 回应关系；
- 对比关系；
- 趋势关系；
- 反例关系。

每张研判卡提供：

- 研判点正文；
- 涉及的事件；
- 支撑事实摘要；
- 证据边界；
- “采用”；
- “暂不采用”。

页面展示自然语言，内部可以保存 `material_id`、`internal_signal_ref`、`relation_id` 和 `evidence_source_id` 作为回溯信息。这些 ID 不要求作者输入，也不作为阶段 3 候选保留、评分或成稿通过的唯一条件。

### 3.2 字段职责

| 字段 | 调整后职责 | 必填规则 |
|---|---|---:|
| `adopted_research_points` | 作者实际采用的研判拓展点，结构化多值字段 | 必填，至少 1 条 |
| `research_basis` | 根据采用清单概括文章研判主线 | 必填 |
| `confirmed_facts` | 支撑采用研判点的具体事实、时间、动作、参与方和来源事实 | 必填 |
| `author_opinions` | 作者明确表达的观点、判断和理由 | 必填 |
| `angle` | 文章从哪个冲突、变化、差异或反例切入 | 必填 |
| `thesis` | 文章最终要证明的命题及成立条件 | 必填 |
| `forbidden_claims` | 待核内容、来源分歧和禁止越界的说法 | 必填，可明确留空 |
| `confirmed_experiences` | 作者可验证的第一人称实践 | 选填，但必须询问是否依赖 |
| `rejected_angles` | 明确舍弃的研判点、事件或角度及原因 | 选填；发生舍弃时追加 |

`editor_question`、`open_questions` 继续作为系统状态字段，不属于作者最终决策，也不传给文章模型作为写作内容。

### 3.3 采用规则

- 页面默认不选择研判点，不能只填写“围绕事件展开”；
- Agent 只能在作者明确角度和命题后，通过 `editorial.research.select` 直接选择最多 3 个具体研判点；工具只接受当前研判报告中的有效 `point_id`，并自动追加去重；不要求作者重复确认；
- 推荐采用 2～4 个互相支持或形成张力的研判点，但不强制凑数；
- 如果文章主线使用事件间关系，至少采用对应的一条事件间研判；
- 没有可靠事件间关系时，不强制加入比较或趋势；
- 不要求采用全部研判点；
- 作者点击“暂不采用”或在对话中明确放弃时，才写入舍弃记录；
- 明确舍弃的方向追加到 `rejected_angles`，并记录原因，防止后续模型重新引入。

## 4. 编辑室交互调整

编辑室的研判面板继续展示完整研判内容，但决策底稿增加明确的取舍动作。

推荐交互顺序：

```text
  查看研判卡
  ↓
  确认支撑事实和证据边界
  ↓
  确认 author_opinions
  ↓
  确认 angle / thesis
  ↓
  Agent 调用研判拓展点工具自动选择
  ↓
  页面展示结果，作者可调整
  ↓
  确认 research_basis
  ↓
  记录不采用方向、禁写边界和实践要求
```

编辑室模型提问时，应优先围绕已选择的研判点提问，例如：

- 这个反常点的真正落差是什么？
- 冲突中谁获得收益，谁承担成本？
- 这个对比关系具体比较的是动作、成本、结果还是商业化能力？
- 这个反例会改变你的判断，还是只用于增加文章张力？
- 哪些内容只能写成待验证问题，不能写成确定事实？

不得让作者重新从空白处泛泛回答“你想写什么”。

## 5. 数据结构

新增产物 `editorial-research-selection.json`：

```json
{
  "candidate_id": "C001",
  "selected": [
    {
      "scope": "internal|inter_event",
      "kind": "anomaly|interest_conflict|divergence|sequence|response|comparison|trend|counterexample",
      "statement": "自然语言研判点",
      "material_refs": ["RM-001"],
      "signal_refs": ["E1:anomaly:1"],
      "relation_refs": ["MR-001"],
      "evidence_source_refs": ["search:S1"],
      "writing_role": "opening_conflict|mechanism|counter_argument|counterexample|reader_impact"
    }
  ],
  "rejected": [
    {
      "statement": "作者明确舍弃的方向",
      "reason": "与当前主线无关或证据不足"
    }
  ]
}
```

`statement` 是人和模型共同读取的主要内容，引用 ID 只用于系统回溯、素材拼装和审计。它不要求文章正文出现 ID，也不把 ID 匹配作为写作门禁。

## 6. 传给文章阶段的研究包

锁定简报不能只传 `research_basis`，必须增加“研判采用清单”：

```markdown
## 研判采用清单

### 事件内
- 采用：具体反常/利益冲突/发散方向
  - 支撑事实：...
  - 表达边界：确定事实 / 作者判断 / 待验证问题

### 事件间
- 采用：具体前后/回应/对比/趋势/反例关系
  - 比较维度：...
  - 支撑事实：...
  - 关系边界：...

### 明确不采用
- 方向：...
  - 原因：...
```

文章 pipeline 传给事实基座、大纲、主写、自然化和审阅阶段的研究包至少包含：

1. 采用的研判点及自然语言说明；
2. 每个研判点的支撑事实、来源摘要和证据边界；
3. 作者的主线、角度、命题和观点；
4. 明确不采用的方向及原因；
5. 每个采用点在文章中承担的作用。

文章模型不需要机械复述研判报告，但不能遗漏作者已经锁定的核心研判点，也不能把明确舍弃的方向重新写回文章。

## 7. 成稿研判贴合度检查

新增 `research-coverage-review.json`，与现有事实门禁分开。事实门禁回答“事实有没有证据”，贴合度检查回答“作者选中的研判有没有被文章兑现”。

```json
{
  "status": "pass|needs_revision",
  "items": [
    {
      "research_point": "一级估值与二级市场商业化定价之间的冲突",
      "status": "full|partial|omitted|contradicted",
      "article_evidence": "第 3、5、8 段",
      "note": "已展开估值机制，但反例差异没有充分展开"
    }
  ],
  "rejected_point_leakage": [],
  "repair_suggestions": []
}
```

检查规则：

- 核心 `research_basis` 未出现或被改成另一条主线：`needs_revision`；
- 已采用的核心研判点完全遗漏：`needs_revision`；
- 支撑性研判点只有提及，没有事实、机制或观点展开：标记 `partial`；
- 明确舍弃的方向重新作为事实或核心观点出现：`needs_revision`；
- 证据不足的研判点必须以限定性判断或待验证问题表达，继续由事实门禁检查。

这项检查不要求文章使用所有研判结果，也不要求没有可靠关系的选题补写事件间关系。

## 8. 实施顺序

### 阶段 1：数据和服务契约

- 增加 `adopted_research_points` 的存储与读取；
- 增加 `editorial-research-selection.json` 产物；
- 保持现有字段的追加、去重和明确删除规则；
- 不改变阶段 3 的候选生成和评分门禁。

### 阶段 2：编辑室表单

- 研判面板按事件内/事件间展示采用卡；
- 增加“采用/暂不采用”操作；
- 采用后自动填入或更新研究清单；
- 明确舍弃时追加 `rejected_angles`；
- `research_basis` 改为对采用清单的总结，不再独自承担素材选择。

### 阶段 3：成稿输入

- 将采用清单和舍弃方向写入锁定简报；
- 将每个研判点对应的事实边界传入事实基座、大纲和写作模型；
- 将研究包传入自然化和审阅阶段；
- 不把原始研判 JSON 全量塞入每次写作请求。

### 阶段 4：贴合度门禁

- 生成 `research-coverage-review.json`；
- 对核心研判点遗漏、主线漂移和舍弃方向泄漏给出返工提示；
- 只执行功能相关测试；完整回归测试按项目约定留到提交 master 前执行。

## 9. 验收标准

1. 编辑室能看到所有可用的事件内、事件间研判拓展点；
2. 页面首次打开不自动选择研判点；角度和命题明确后，编辑室 Agent 能提出不超过 3 条针对当前命题的研判点建议，作者可以确认、取消或补选，不需要手填内部 ID；
3. `adopted_research_points` 至少包含一条具体研判点；
4. 采用清单、支撑事实、证据边界和舍弃方向能进入锁定简报；
5. 大纲和写作模型能收到采用清单，而不是只有一句 `research_basis`；
6. 成稿检查能够区分 `full`、`partial`、`omitted` 和 `contradicted`；
7. 核心研判点遗漏或舍弃方向泄漏时，能够生成明确返工提示；
8. 不强制文章采用全部研判点，也不强制没有可靠关系的文章补写事件间关系。

## 10. 与既有方案的边界

- 研判主流程仍由 [讨论研判改造方案](./discussion-oriented-topic-research-adjustment-plan.md) 定义；
- 阶段 3 仍只根据研判报告生成候选，不增加候选必须绑定关系 ID 的要求；
- T/J/A/C/F 评分不因本方案改变；
- 文章正文仍在编辑室阶段抓取真正引用的 URL；
- 本方案解决的是“作者选中的研判点如何进入并兑现到文章”，不是重新判断事件关系真假。
