# 从讨论研判到高讨论文章的选题链改造方案

状态：阶段 0～3 已实施；研判已改为“每个 Top-K 事件一次模型联网交互并直接返回 Markdown”；正文抓取已延迟到编辑室
日期：2026-09-03

## 1. 改造目标

这次改造的目标不是让系统多生成几个标题，而是让一个候选选题能够继续发展成一篇有讨论度的文章。

高讨论文章至少需要同时具备：

1. 一个公开事实或正在发生的变化；
2. 一个具体的反常、利益/成本/责任冲突，或多个事件之间的可比较关系；
3. 一个可以被证据支持、反驳或修正的核心命题；
4. 明确的支持证据、反方解释和事实边界；
5. 与读者收入、工作、机会、成本或选择相关的实际问题。

因此流程要从：

```text
事件卡 → 研判疑问 → 候选标题
```

改成：

```text
事件卡
  ↓
冻结非项目事件 Top-K
  ↓
每个事件一次模型联网研判
  （事件内 + 事件外，直接返回 Markdown）
  ↓
程序保存报告、来源和结构索引
  ↓
模型基于研判报告生成候选选题
  ↓
脑暴、编辑室核验正文并承接成稿
```

## 2. 最新批次复盘结论

以 `2026-09-02-3a07b08bea-orchestrated` 为例：

| 指标 | 结果 | 暴露的问题 |
|---|---:|---|
| Top-K 事件 | 30 | 研判范围较大，质量差异明显 |
| 研判素材 | 76 条 | 其中 64 条为 `needs_review` |
| 已验证素材 | 12 条 | 可直接支持确定性表达的素材较少 |
| 事件间关系 | 0 条 | 本批没有形成对比、回应、趋势或反例文章素材 |
| 候选选题 | 6 条 | 全部来自事件内研判 |
| 搜索任务 | 12 个 | 全部用于事件内求证，事件间搜索任务为 0 |

现有流程已经能够发现反常和利益冲突，但还存在五个关键断点：

1. 研判素材没有完整转化为可写的论证素材；
2. `needs_review` 内容过多，容易和已验证事实混在一起；
3. 事件间关系阶段没有稳定产出实际关系素材；
4. 脑暴仍可能把事件卡包装成标题，缺少命题、反证和文章结构约束；
5. 单条评分和整批组合没有充分区分，多个相近事件角度容易同时进入总榜。

本方案围绕以上五点改造，不再把补齐时间线作为主要目标。

## 3. 目标范围和非目标

### 3.1 研判范围

- 只对排除项目图文后的 T 榜 Top-K 事件执行讨论研判；当前默认 `Top-K = 8`，系统配置允许选择 `5 / 8 / 10`，所有单事件研判共用同一批事件范围；
- Top-K 是研判范围，不代表所有事件都必须产生候选选题；
- 事件内研判逐事件隔离；
- 事件间研判只处理模型认为值得验证的候选对、候选组和外部参考事件。

### 3.2 搜索重点

外部搜索只服务以下五类内容：

#### 事件内

- 反常证据：预期、承诺、行业基线或主体过去做法，与当前结果的落差；
- 利益冲突证据：收益、成本、责任或解释权如何在参与方之间分配；
- 可发散方向的基线和影响：谁会受影响、影响如何发生、后续什么信号可以验证或推翻判断。

#### 事件间

- 关联发现：围绕 `who / where / how` 延展同一主体的其他动作、近似主体的同类动作或不同动作的反差；
- 对比关系：两个事件在动作、策略、收益、成本、责任或结果上的具体差异；
- 趋势关系：至少三个独立事件是否指向同一变化；
- 反例关系：哪个事件与已有趋势或判断相反。

### 3.3 明确不做

- 不把完整事件时间线作为默认搜索产物；
- 不用关键词相同直接建立事件关系；
- 不让搜索结果直接生成事实结论或评分；
- 不把外部参考事件直接当作 Top-K 主事件；
- 不为了凑满核心 8 条而保留相近选题；
- 不增加单独的发布后 Q 评分，公众号已有阅读、分享、评论数据由既有复盘流程承接。

## 4. 新的阶段划分

### 阶段 0：冻结研判范围

程序完成事件归并、事件卡生成、T 排名、排除 `github_project` 等非文章事件，并冻结可配置的 Top-K（`5 / 8 / 10`）。阶段 0 只保存范围、事件来源指针和证据等级，不生成讨论结论，也不判断文章价值。

`topk-research-scope.json` 在模型调用前写入，作为后续唯一范围快照。只有进入该快照的事件才能进入模型研判。

### 阶段 1：单事件完整模型研判

对每个 Top-K 事件执行一次模型交互。当前事件输入完整事件卡、来源摘要/URL 和其他 Top-K 事件的精简比较索引；模型可在同一次交互中使用原生 `web_search`，直接完成事件内和事件外研判，并返回 Markdown 报告。

事件内必须覆盖：

- 反常：预期、承诺、行业基线或主体过去做法，与当前结果的具体落差；
- 利益冲突：参与方的收益、成本、责任或解释权如何不对称；
- 可发散方向：基线、影响、替代解释、反例和下一步问题。

事件外必须覆盖：

- 当前事件与其他 Top-K 事件的前后、回应、对比、趋势或反例关系；
- 通过 `who / where / how` 向外发现的同一主体不同动作、近似主体同一动作、同一对象不同策略、不同动作结果反差和独立反例样本。

只有存在具体时间、动作、回应、结果或影响差异时才建立关系；关键词相同、主体相同或对象相同不算关系。对比必须写出具体差异，趋势至少需要三个独立事件，反例必须明确反驳的趋势或判断。

模型直接返回最终 Markdown，不再分为假设和验证，也不生成中间 `search_tasks`。来源只记录标题、URL 和搜索摘要，正文抓取延迟到编辑室。

### 阶段 2：程序整理模型研判素材

程序不再进行语义判断，只做确定性整理：

- 保存每个事件的原始 Markdown 研判报告；
- 按报告标题建立事件内信号和事件间关系索引；
- 合并重复关系；
- 绑定模型报告中列出的来源、URL 和摘要；
- 生成素材 ID 和事件 ID 关联；
- 保留“待核实”边界，不因没有正文丢弃模型研判。

`verified_research_materials` 名称保持兼容，但新的状态重点是 `model_reported`、`needs_review` 和 `verified`。其中 `model_reported` 表示模型已完成联网研判，不等于编辑室已核验正文。

### 阶段 3：基于研判素材生成候选选题

阶段 3 只读取单事件模型研判报告及其整理后的关系/信号索引，生成候选选题。候选必须明确来自：

- 事件内反常；
- 利益、成本或责任冲突；
- 可发散方向；
- 事件间前后、回应、对比、趋势或反例关系。

候选只基于研判报告生成，不能把事件摘要脱离报告改写成标题。`material_ids`、`internal_signal_refs`、`relation_ids` 和来源是可选的回溯信息，不是阶段 3 的必填字段，也不参与候选保留或关系型选题比例门禁。阶段 3 不重新联网、不重新判断关系，也不把评分当作作者立场。

### 阶段 4：研究驱动脑暴和编辑室承接

脑暴和编辑室读取候选对应的模型研判报告、关系索引和证据边界，围绕报告中的落差、利益结构、关系变化、可写角度和观点种子提问。选题确定后，编辑室再对真正引用的 URL 执行 `url-fetch`，补充文章事实基座和正文证据。

阶段 4 不重复做批次研判，也不新增发布后 Q 评分；公众号阅读、分享和评论数据继续由既有复盘流程承接。

## 5. “已验证研判素材”契约

每条素材至少包含以下字段：

```json
{
  "material_id": "RM-internal-anomaly-E1-1",
  "material_type": "internal_anomaly|internal_interest_conflict|internal_divergence|inter_event_sequence|inter_event_response|inter_event_comparison|inter_event_trend|inter_event_counterexample",
  "status": "verified|needs_review|rejected",
  "anchor_event_ids": ["E1"],
  "reference_event_ids": [],
  "fact_statement": "可直接由来源支持的事实",
  "expected_or_baseline": "预期、承诺、行业基线或过去做法",
  "observed_result": "当前事件实际发生的结果",
  "difference_or_conflict": "落差、利益差异或关系差异",
  "parties": ["参与方 A", "参与方 B"],
  "mechanism": "为什么该事实会形成反常或利益冲突",
  "reader_impact": "对具体读者的工作、收入、成本或选择有什么影响",
  "alternative_explanations": ["可能的反方解释"],
  "writing_angles": ["从成本承担者切入"],
  "thesis_seeds": ["可被支持或反驳的观点种子"],
  "open_questions": ["仍需确认的问题"],
  "evidence_source_ids": ["search:ST-001:1"],
  "evidence_clips": [
    {
      "source_id": "search:ST-001:1",
      "url": "https://example.com",
      "title": "来源标题",
      "excerpt": "与本素材直接相关的搜索摘要片段",
      "evidence_level": "summary_only"
    }
  ],
  "evidence_boundary": "允许确定表达和必须保留的限定语"
}
```

### 5.1 证据等级门禁

| 证据等级 | 可以做什么 |
|---|---|
| `full_text` | 由编辑室按选题抓取后，支持较确定的事实、反常、利益冲突和事件关系判断 |
| `summary_only` | 研判阶段形成待核素材、低确定性反常/冲突判断和发散问题 |
| `repository_meta` | 说明项目基本属性，不能推断用户影响和利益冲突 |
| `title_only` | 只能作为搜索线索 |

规则：

- 每条素材必须至少有一个可回溯来源 URL 或事件卡来源指针；
- 研判阶段不把 `summary_only` 升级成 `full_text`，也不因缺少正文删除素材；
- `needs_review` 可以进入候选选题，但只能进入问题、限定语和待验证项，不能作为确定事实；
- 选题被编辑室选中后，才对其关键来源执行正文抓取，并在文章事实基座中重新确认；
- 文章命题必须区分事实、解释和作者判断；
- `evidence_clips` 必须能让编辑快速定位原文，而不是只保存来源 ID。

### 5.2 当前缺口对应的修复

模型报告整理出的素材中，`writing_angles` 和 `thesis_seeds` 为空时，阶段 1 的模型输出必须补齐：

- 至少一个可写角度；
- 至少一个观点种子；
- 至少一个反方解释或替代原因；
- 对发散方向补齐 baseline、impact 和验证条件。

如果模型无法补齐，素材可以保留为 `verified` 事实，但不得直接生成高确定性观点型候选。

### 5.3 联网能力边界

| 阶段 | 模型联网 | 可使用的输入 | 产物定位 |
|---|---|---|---|
| 阶段 0 | 关闭 | T 排名、事件卡和来源指针 | Top-K 范围快照 |
| 阶段 1 | 开启 | 当前事件完整资料、其他 Top-K 精简索引、关系候选 | 单事件最终 Markdown 研判报告 |
| 阶段 2 | 关闭 | 单事件报告、模型来源和关系索引 | 可追溯研判素材 |
| 阶段 3 | 关闭 | 研判报告和研判素材 | 候选选题 |

阶段 1 使用 Responses API 显式传入 `tools: [{"type":"web_search"}]` 和 `tool_choice: "auto"`。模型供应商必须配置 Responses 协议。模型自己决定是否搜索、搜索什么以及是否引入外部关系，程序不再生成 `search_tasks`，也不再拆分假设和验证阶段。

模型输出使用 Markdown，不使用严格 JSON。输入快照仍记录 `tool_choice`、`web_search_mode`、模型调用 ID、工具调用元数据和完整模型报告；这些是审计数据，不是模型正文格式约束。若模型返回搜索过程而没有研判报告，该事件保留失败记录，不阻塞其他 Top-K 事件。

## 6. 研判联网与资料边界

### 6.1 单事件联网交互

每个 Top-K 事件只执行一次应用层模型交互。模型可以自行选择查询词和搜索范围，在同一次交互中完成事件内和事件外研判，并直接返回 Markdown 报告。程序只记录调用审计、保存报告、整理来源和建立索引，不生成 `search_tasks`，也不把联网拆成后续验证阶段。

其他 Top-K 事件只以精简索引进入当前事件的上下文，时间关系图只负责提供候选比较范围，不替模型判断语义关系。

### 6.2 搜索重点

模型联网只围绕以下内容：

1. 事件内反常的行业基线、公开承诺、主体过去做法与当前结果的落差；
2. 事件内利益冲突中的参与方收益、成本、责任和解释权；
3. 可发散方向的基线、影响、替代解释和反例；
4. 事件间的前后、回应、对比、趋势和反例；
5. 通过 `who / where / how` 发现的同一主体不同动作、近似主体同一动作、同一对象不同策略和不同动作结果反差。

模型不需要为所有事件平均分配查询。没有足够讨论价值的事件可以只返回“暂无足够依据”，不会被程序补写成新闻复述。

### 6.3 研判与编辑室的资料边界

- 研判阶段：只使用模型原生联网能力完成事件内和事件外研判；模型报告返回回答、引用 URL、标题、摘要/摘录和证据边界；
- 研判阶段：不调用 `url-fetch`，不调用 Firecrawl Scrape，不批量抓取报道正文；
- 编辑室阶段：选题确定后，才对文章真正引用的关键 URL 执行 `url-fetch`，必要时再用 Firecrawl Scrape 处理动态页面、反爬或本地抓取失败；
- 研判阶段引用统一标记为 `summary_only`，不能因为模型给出 URL 就升级为 `full_text`；
- 供应商没有原生联网能力时，`web_search_mode` 必须记录为不可用，相关报告只能保留为待核，不能标记为已验证。

## 7. 研究驱动脑暴：从选题标题变成论证卡

### 7.1 脑暴输入

脑暴输入必须显式包含：

- `verified_research_materials`；
- 对应的事件内信号；
- 对应的事件间关系；
- 支持证据和来源片段；
- 反方解释和事实边界；
- 账号定位、读者和近期内容。

事件标题和摘要只能帮助模型识别背景，不能作为独立选题依据。

### 7.2 脑暴输出

每个候选输出一张论证卡：

```json
{
  "candidate_id": "C001",
  "status": "PASS|NO_ANGLE|NEED_MORE_RESEARCH",
  "research_basis_refs": {
    "material_ids": ["RM-001"],
    "internal_signal_refs": ["E1:anomaly:1"],
    "relation_ids": [],
    "evidence_source_ids": ["search:ST-001:1"]
  },
  "discussion_question": "文章真正要回答的问题",
  "core_thesis": "可被证据支持或反驳的核心判断",
  "supporting_facts": ["支持判断的事实"],
  "counter_argument": "最强反方解释",
  "judgment_boundary": "什么条件下该判断不成立",
  "parties_and_interests": "各方获得什么、承担什么",
  "reader_job": "读者看完要完成的判断或行动",
  "article_structure": [
    "事实和冲突如何出现",
    "证据、机制和反方解释",
    "对读者意味着什么"
  ],
  "must_verify": ["成稿前必须再次确认的事实"],
  "title_directions": ["标题方向一", "标题方向二"]
}
```

### 7.3 脑暴质量门禁

候选只有同时满足以下条件才能 `PASS`：

- 至少绑定一条有效研判素材；
- 至少绑定一个具体证据来源；
- 核心问题不是“发生了什么”，而是“为什么会这样/谁承担代价/这意味着什么”；
- 核心判断不是无证据的必然因果；
- 存在可表达的反方解释或替代判断；
- 有具体读者和可感知的利益；
- 文章结构能够围绕命题推进，而不是按新闻来源逐条复述。

以下情况只能 `NO_ANGLE` 或 `NEED_MORE_RESEARCH`：

- 只有标题或摘要；
- 只有待核发散问题，没有已验证事实；
- 只能写“某公司发生了某事”；
- 只有主体相似，没有可比较维度；
- 观点使用“必然、终将、彻底、一定”等强因果表达，但证据不足。

## 8. 候选组合和评分优化

### 8.1 单条评分保留，组合选择另行处理

T/J/A/C/F 继续用于衡量单条选题质量，但不能让单条 F 代替整批组合判断。

- T：事件热度，不因标题包装重复增加；
- J：候选对应研判报告中的判断增量；结构化素材和关系 ID 只作为可选回溯信息，不因候选未回填 ID 而归零；
- A：论证卡是否具备文章化质量；
- C：市场饱和、历史重复和本批次内部重复；
- F：单条综合排序，不代表整批内容组合最优。

### 8.2 总榜组合规则

- 同一事件核心榜默认最多 1 条；
- 同一主体、同一项目、同一冲突方向的近似候选只保留最高价值者；
- 同事件其他角度保留在“同事件备选”，不占核心席位；
- 有确认事件间关系的候选优先补充不同事件和不同关系类型；
- 核心 8 条不足时允许少于 8 条，不用相近候选凑数；
- `组合推荐` 必须实际影响候选选择，不能只生成一段解释文字。

### 8.3 竞争复排输入

综合复排模型除标题、角度和包装外，必须读取：

- 研判素材 ID；
- 事件内/事件间关系类型；
- 支持证据数量和质量；
- 反方解释；
- 与其他候选共用的事件、主体和材料。

它需要输出明确的重复对象和保留理由，而不是只给一个饱和度数字。

## 9. 编辑室与成稿承接

选题池点击候选时，必须能看到：

- 事件信息；
- 事件内反常、利益冲突和发散方向；
- 事件间关系及具体比较维度；
- 已验证研判素材；
- 支持证据、来源 URL 和证据等级；
- 反方解释和未确认边界；
- 脑暴形成的核心问题、命题和文章结构。

编辑室不需要重新看评分来决定文章怎么写。编辑室应根据论证卡进行针对性提问，例如：

- 这个冲突中真正承担成本的是谁？
- 现有证据能支持“管理问题”，还是只能支持“管理争议”？
- 反方解释是否足以改变文章结论？
- 这个事件和另一个事件的比较维度是否成立？
- 读者看完以后要改变哪个判断或行动？

成稿简报必须携带：

1. 核心讨论问题；
2. 文章命题及其成立条件；
3. 事实基座；
4. 支持证据和来源片段；
5. 反方解释和待核事项；
6. 读者利益；
7. 文章结构；
8. 不得越过的事实边界。

文章模型只能在该简报和证据包内写作。没有证据支持的内容必须使用限定表达或列为待核，不得为了增强讨论度自行补造事实。

## 11. 实施顺序

### 阶段 A：落实单事件模型研判

- 每个 Top-K 事件只调用一次模型，模型在同一交互中完成事件内和事件外研判并返回 Markdown；
- 在 `discussion-research-input.json` 记录每次请求的 `tool_choice`、联网模式、调用 ID、工具调用和用量。

### 阶段 B：整理报告和研判素材

- 保存每个事件的原始 Markdown 报告；
- 只按明确标题和字段整理反常、利益冲突、可发散及事件间关系，不用关键词或正则重新判断语义；
- 绑定报告列出的来源编号、标题、URL 和摘要，并保留 `model_reported` / `needs_review` 边界；
- 对趋势和反例保留模型明确写出的事件数量、比较差异和反驳对象。

### 阶段 C：基于报告生成候选选题

- 将单事件模型报告和结构化研判素材作为候选生成的唯一研究依据；
- 候选只需基于研判报告形成可讨论命题；报告素材、内部信号、事件间关系和来源可以作为可选回溯信息；
- 允许 `needs_review` / `model_reported` 进入候选，但必须使用待核限定语；
- 阶段 3 不重新联网、不重新判断关系，也不把事件摘要改写成标题。

### 阶段 D：升级组合选择和编辑室

- 增加同事件、同主体、同冲突方向的组合去重；
- 将组合推荐从解释文字改为实际选择规则；
- 候选详情展示证据、关系和论证卡；
- 成稿简报完整继承研判素材和事实边界。

## 12. 验收标准

### 研判素材

1. 每条 `PASS` 候选至少绑定一条研判素材和一个来源；
2. 已验证素材具备事实、解释、读者影响、反方解释和写作角度；
3. `needs_review` 不会被写成确定事实；
4. 每条素材可以从文章回溯到模型报告、来源 URL 和搜索摘要；正文片段在编辑室选题后补齐。

### 事件间关系

5. 单事件模型报告能够产出有明确端点和差异依据的事件间关系；
6. 对比关系能够列出具体比较维度和差异；
7. 趋势关系至少有 3 个独立事件；
8. 反例关系明确反驳对象；
9. 主题类比和事实关系不会混用。

### 脑暴和文章命题

10. 脑暴输出核心讨论问题、核心判断、支持证据、反方解释和成立条件；
11. 候选不是事件摘要改写；
12. 文章结构围绕命题推进，而不是按来源流水账复述；
13. 编辑室可以直接根据论证卡提出针对性问题；
14. 成稿简报完整继承素材 ID、来源 ID 和事实边界。

### 榜单组合

15. 同一事件默认不在核心榜重复占位；
16. 组合推荐实际影响核心/备选选择；
17. 候选不足时允许少于核心 8 条，不用相似选题补齐；
18. T/J/A/C/F 仍保持原有定义，不把外部搜索数量直接当作讨论度。

## 13. 判断改造是否成功

重跑研判后，不只看候选数量或 F 分，而要检查：

- 是否形成至少一条完整的“事实—冲突—机制—观点—反方”链；
- 文章模型能否只根据简报写出清晰的讨论问题和论证结构；
- 文章是否能回答读者“这和我有什么关系”；
- 不同候选是否真的改变了核心判断或读者任务；
- 事件间关系是否提供了单事件新闻之外的信息增量；
- 编辑能否准确指出每个判断对应的来源和证据边界。

最终目标不是让所有事件都有选题，而是让留下来的选题具备继续写成有事实、有冲突、有观点、允许读者分歧的文章的条件。
