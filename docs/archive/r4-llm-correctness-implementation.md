# R4 LLM 正确性实施记录

## R4.1 输出预算（已完成）

- 调用方显式 `maxOutputTokens` 作为硬上限，优先于 purpose profile，不再被更大的阶段默认值覆盖。
- 未显式指定上限时继续使用 purpose profile，并允许截断后的自适应扩容。
- `adaptiveOutput:false` 和分块任务 profile 继续固定预算，不执行扩容重试。
- thinking reserve 只对 `supportsThinkingToggle:true` 的供应商生效；不支持开关的兼容供应商不会被静默追加输出额度。
- `model_calls.output_budget_json` 持久化最终预算、来源、thinking reserve、thinking 状态和供应商能力，用于解释成本与截断行为。
- 数据库版本升级为 2，R4 审计列通过独立事务迁移，已完成版本 1 的数据库不会重复运行 R3 基线修复。

## R4.2 重试语义（已完成）

- `complete` 与 `streamComplete` 都对 `finish_reason=length` 执行至多一次自适应扩容。
- 流式首轮处于可扩容模式时暂存正文增量；首轮完整才释放，截断时丢弃残稿，避免 UI 拼接两轮内容。
- 429 与 5xx 在单次请求超时边界内执行最多 3 次有限指数退避；其他 4xx 不重试。
- `AbortSignal` 贯穿压缩摘要、thinking 回退、截断重试和 HTTP 退避；取消后返回稳定错误码 `MODEL_CALL_ABORTED`，不继续请求。
- 流式与非流式共用 thinking 空内容回退条件和预算决策。

## R4.3 评分与内容门禁（已完成）

- 突发模式 `audienceRelevance` 使用空值合并，合法 `0` 分不再被替换为默认分。
- 突发评分量纲矛盾只依据维度总分与生产建议，不再依赖理由或故事板条目数量。
- 来源脚注只识别显式 `[^id]` 定义及来源标签，普通 `1.`/`2.` 有序列表不再算作事实来源。
- `resolveArticleLength` 明确拒绝 NaN、负值、非正上限及 min/max 倒置配置。
- 早报质量归一化使用当前配置上限，移除固定 `1800` 判断。
- 每轮布局审计先删除旧报告；审计进程失败或未生成新报告时立即失败，禁止复用旧的通过结果。
- 脑暴单卡在普通与极简两次均失败后写入 `pipeline_failures`，并继续处理剩余候选。

## R4.4 Prompt 注入和上下文（已完成）

- 新增共享 `context-safety`：不可信数据定界、段落/换行/代码围栏安全截断、会话双预算和 Markdown 内联数据转义。
- 编辑会、自主写作和自定义图文统一限制最近 24 条消息、总计约 24000 字符；保留最新对话，超长单条带明确截断标记。
- 对话、项目材料、事件来源和突发素材明确标注为不可信数据，其中的命令、角色声明和工具要求不得执行。
- 来源截断不再使用无标记 `slice`，优先在语义边界截断，并闭合未完成代码围栏。
- 突发事实基座写入 Markdown 前清理模型生成的标题、换行、表格分隔符和代码围栏控制符。
- 账号上下文按 `workspaceRoot` 动态解析并按文件路径缓存，支持显式刷新；不再在模块加载时永久绑定 `process.cwd()`。

## R4.5 JSON 解析统一（已完成）

- 新增共享 `model-json` 模块，统一 Markdown 围栏剥离、说明文字中的主对象/数组定位和字符串内括号处理。
- `finish_reason=length` 与结构未闭合统一归类为 `MODEL_JSON_TRUNCATED`；其他语法或顶层类型错误归类为 `MODEL_JSON_INVALID`。
- 提供一次性结构修复入口；无论修复成功或失败，repair 回调最多执行一次，失败使用 `MODEL_JSON_REPAIR_FAILED`。
- 无效输出统一写入 `model_calls` 的 `invalid_output` 状态，审计错误包含稳定、可检索且不暴露原始输出的错误码。
- 编辑会、自定义图文、文章、早报、教程、研判、配图规划和排版设计已切换到共享解析器。

R4 至此完成。后续进入 R5 主题、插件与公共模块收敛。
