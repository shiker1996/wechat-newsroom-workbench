# R3 数据完整性实施记录

## 完成范围

- 引入 `schema_migrations` 与显式 `WORKBENCH_SCHEMA_VERSION`，旧式结构修复只在版本升级时执行，并由事务包裹。
- SQLite 连接设置 `busy_timeout=5000`；应用退出时执行 WAL checkpoint 并关闭数据库。
- 服务使用进程锁阻止同一工作区被第二实例同时打开，避免后启动实例误把首实例任务标记为中断。
- 文稿保存、版本写入与历史裁剪组成同一事务；社交评分和候选轨道更新组成同一事务；启动恢复的四类状态更新组成同一事务。
- 批次 ID 改为密码学随机后缀并在唯一冲突时重试。
- 候选编号改为按同前缀现存最大序号递增，删除候选后不会因 `COUNT(*)` 复用已有编号并跳过新热点。
- 为 `candidate_row_id IS NULL` 的批次级文稿增加部分唯一索引；升级时只保留同批次、同类型的最新记录。
- 采集任务和 AI 任务的终态内存记录限制为最近 100 条，避免常驻进程持续增长。

## 兼容性说明

- 首次打开未版本化数据库时执行 R3 基线迁移；后续启动仅检查版本与外键完整性。
- 高于当前程序支持版本的数据库会被明确拒绝，避免旧程序误写新结构。
- 单实例锁包含 PID；进程异常退出留下的锁在确认 PID 不存活后自动清理。
- 批次级重复文稿迁移属于有意的数据修复：保留 ID 最大（最新保存）的记录，相关旧版本随旧文稿级联清理。

## 验证

新增 `test/r3-data-integrity.test.mjs`，覆盖：

- 迁移版本持久化与重复启动幂等；
- NULL 候选的批次级文稿唯一性；
- 删除候选后的编号碰撞回归；
- 单实例锁拒绝重复持有并可在释放后重取。

现有 Store、旧版数据库升级、备份恢复与重构契约测试继续作为兼容性门禁。

## 后续阶段

R3 尚未扩展到跨文件系统与数据库的完全原子提交；备份恢复仍通过安全备份、暂存目录和交换回滚提供补偿语义。更广泛的进程树终止、CDP 恢复和所有外部网络超时统一归入后续运行时治理阶段，避免与数据库迁移发布耦合。
