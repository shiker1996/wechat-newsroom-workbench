# 工具图文故事板最小调整方案

> 状态：已按最小范围实施（2026-08-10）

## 1. 目标

结合账号近期流量表现，只优化工具图文故事板的内容方向：

1. 从“介绍热门仓库”转向“帮助具体读者完成具体任务”。
2. 封面优先呈现任务、痛点和结果方向，项目名作为辅助信息。
3. 区分项目文档、实际运行和未知项，避免把 README 整理写成亲测。
4. 快速开始正确说明安装命令和用户参数。
5. 结尾提供适用对象、不适用对象和使用前注意事项。

## 2. 最小改动结论

现有 `repository-card-storyboard` 主技能已经要求故事板覆盖痛点、能力、快速上手、适用场景与限制，因此不需要改主技能、账号上下文或运行时代码。

实施时只修改两处：

1. `skills/repository-card-storyboard/references/storyboard.md`
   - 在现有 JSON 契约和补充要求中增加少量生成指导。
2. `test/social-card-storyboard-p0.test.mjs`
   - 更新 repository 提示词语义快照。
   - 增加少量规范存在性断言。

不新增文件、不新增字段、不新增生成后的检查阶段。

## 3. Reference 拟增加的内容

保持现有 JSON 字段、`recommended_pages: 4到7` 和密度预算不变，只增加以下规则。

### 3.1 任务导向

- `target_reader` 同时写明具体角色和使用场景。
- `pain_point` 写明读者正在完成的任务、当前阻碍或成本。
- `tool_positioning` 说明工具在该任务中的作用。
- Star、Trending 和项目知名度只作为证据，不作为读者价值本身。

### 3.2 封面表达

- 主标题优先使用“具体任务或问题 + 结果方向”。
- 陌生项目名作为副信息，不独占主标题。
- 不使用文档或运行记录无法支持的速度、性能和效果承诺。

### 3.3 页序建议

运行时继续允许 4～7 页。技能优先使用以下结构，但不强制凑页：

1. 封面：任务或问题 + 工具定位。
2. 痛点：具体场景和当前成本。
3. 能力：与任务直接相关的机制。
4. 可选能力或场景页。
5. 快速开始：安装、启动和必要配置。
6. 结尾：适合、不适合和使用前注意事项。

### 3.4 证据表达

- README、仓库元数据、LICENSE 和 Release 只能表述为“项目文档显示”或“项目提供”。
- 只有输入中存在明确运行记录时，才能写“实测”“跑通”和具体耗时。
- 没有资料支持的权限、网络、成熟度、兼容性或性能直接标记为未核验。
- 不新增 `evidence_level` 字段，继续使用现有 `evidence` 和 `must_disclose`。

### 3.5 命令与参数

- 保留 README 中真实存在的安装和启动命令。
- `<commit>`、`YOUR_TOKEN`、`$API_KEY` 等可能是正常用户参数，不一律删除。
- 对需要替换的值说明用途，优先改写为语义清晰的变量名，如 `$COMMIT_SHA`。
- 命令含用户参数时，不得写“复制即用”或“无需配置”。
- README 没有完整命令时写操作说明，不补造命令。

### 3.6 结尾

- 优先说明适合哪些角色和场景。
- 说明不适合的约束条件。
- 说明使用前需要确认的权限、网络、版本、成本或安全事项。
- 不用“点赞、收藏、转发”代替内容结论。

## 4. 明确不改

- 不修改 `skills/repository-card-storyboard/SKILL.md`。
- 不修改 `lib/domain/social-card-gate.mjs`，保留原有 10 项 CARD GATE。
- 不修改 `lib/domain/social-card-storyboard-contracts.mjs`。
- 不修改图文生成按钮或页面状态。
- 不修改账号上下文、数据库、评分、渲染、构图、布局审计和交付流程。
- 不自动重写已有故事板。

## 5. 验证方式

1. 运行 `skill-creator` 结构校验。
2. 运行 `test/social-card-storyboard-p0.test.mjs`。
3. 使用 C009、C011 的现有事实基座做只读离线样例验证：
   - C009：检查含参数命令是否被正确解释，而不是简单删除。
   - C011：检查任务导向、文档边界和结尾注意事项。
4. 不写数据库、不覆盖当前故事板、不调用整组图文生成。

## 6. 验收标准

- 仓库运行时代码与调整前一致。
- 原有 CARD GATE 数量和判断保持不变。
- 故事板更突出具体读者任务，而不是项目热度。
- README 内容不会被写成作者亲测。
- 用户参数得到解释，不被误判为错误命令。
- 结尾提供适用范围和使用前注意事项。

评审通过后，按“1 个 reference + 1 个测试文件”实施，不扩大范围。
