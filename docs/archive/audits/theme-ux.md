# 主题视觉 UX 审查

日期：2026-08-02

## 审查范围

- 主题中心总览与主题入口
- 文章主题选择器
- 图文主题选择器

## 截图证据

> 原始截图已从仓库移除以减小体积（2026-08-02，git 历史仍可追溯）；需要时可在本地工作台重新截取：主题中心总览、文章主题选择器、图文主题选择器、文章正式编译样稿、主题编辑器图文样稿、图文正式画布。

## 步骤与健康度

1. 进入主题中心：健康度良好。文章与图文入口被明确分开，AI 创建、复制和我的主题都有入口。
2. 浏览文章主题：健康度中上。预览统一、可比较，但主题之间的差异主要集中在颜色、标题和卡片外观，正文节奏的差异在缩略图中不够突出。
3. 浏览图文主题：健康度中上。14 个主题覆盖面足够，暗色、纸艺、野兽派和极简方向辨识度较好；但卡片都使用相同示例内容与同一页骨架，用户不容易判断“适合什么内容”。

## 主要发现

## 正式编译样稿后的新增发现

### P1：图文主题的视觉差异仍主要停留在“换色与装饰”

证据：对 14 个图文内置主题逐一调用正式主题预览并渲染封面、内容页、步骤页、对比页和结尾页后，页面仍普遍沿用相同的 `page-content-stack`、标题位置和内容块节奏；变化最明显的是背景、边框、阴影、纹理与标题配方。

影响：用户会觉得主题有很多，但实际阅读体验接近同一模板的换肤，主题的长期记忆点不足。

建议：给图文主题增加“页面骨架配方”层，但仍保持安全白名单。例如 Editorial 使用标题跨栏 + 内容双栏，Terminal 使用信息轨道 + 代码面板，Paper 使用不对称留白 + 纸张错位，High-impact 使用大标题占比 + 强色块分区。骨架只改变页面构图，不改变故事板内容顺序。

### P1：图文封面下半部分普遍留白过大

证据：正式画布截图中，封面标题和眉题集中在上半部，卡片下半部大面积空白；在 14 套主题的正式截图中都能观察到相同现象，只是颜色和装饰不同。

影响：封面视觉重心偏上，主题配方没有充分利用封面作为“第一张叙事页”的机会。

建议：让封面配方明确选择一个安全的下半部承载物：导语、关键结论、数据摘要、主题标签或装饰性图形。不同配方可选择不同承载物，但必须受密度预算和长标题门禁约束。

### P1：文章主题的正文节奏没有跟随主题性格充分变化

证据：暖纸杂志正式样稿中，导语、引用、列表、表格、代码之间出现较大的均匀留白；黑白快讯更紧凑，暗色终端的规则线和代码块节奏更强，但两者的正文内容结构仍基本相同。

影响：文章主题的“杂志 / 快讯 / 终端”语气主要由标题和色彩传达，阅读长度、信息密度和重点出现频率没有形成稳定差异。

建议：为文章主题补充受控的阅读节奏档：舒展长文、标准叙事、高密度快讯。节奏档同时约束章节间距、段落间距、引用高度、列表密度和表格行高，避免只调颜色和标题。

### P2：正式预览需要更明确地展示“连续阅读状态”

证据：当前预览可以展示固定样稿，但主题差异需要用户在长画布中滚动观察；单张封面或首屏无法判断中段、结尾页和组件之间是否仍然协调。

建议：预览增加“首屏 / 中段 / 结尾”锚点或三段缩略导航，并提供“连续滚动检查”状态。主题选择和主题编辑都应复用同一组正式编译样稿。

### P1：主题选择仍偏“看风格”，缺少“按内容任务选”

证据：两个选择器都以 `全部 / 内置主题 / 我的主题` 作为主要导航，主题卡只展示视觉缩略图、名称与一句描述。

影响：用户需要先理解主题，再自己把主题映射到“深度文章、快讯、教程、数据卡、事件卡”等任务；AI 自动匹配的能力没有在选择器中形成可见的决策辅助。

建议：增加轻量内容意图筛选或标签，例如“深度观点 / 技术教程 / 快讯 / 数据对比 / 事件图文”。主题卡显示“推荐场景”和“阅读密度”，默认按场景筛选后再按视觉浏览。

### P1：缩略预览中的版式差异还不够明显

证据：文章选择器中的六套预览都使用同一组示例文案和近似结构；图文选择器的 14 套预览也共享“核心结论 + 信息卡片 + 重点信息”的样稿骨架。

影响：用户能看到配色，但不容易判断标题层级、正文节奏、引用/列表/表格和结尾页的真实差异，容易出现“换了颜色但没换体验”的感受。

建议：每个主题使用自己的代表性结构：文章至少轮换“长段落 + 引用”“步骤 + 代码”“数据表 + 结论”；图文至少展示封面、内容页和结束页三张缩略帧，封面标题、数据块、步骤块随配方变化。

### P2：主题卡信息层级可以更快完成比较

证据：主题名称、版本、描述位于预览图下方；选中状态主要通过边框和角标表达。

影响：在 6–14 个主题的网格中，用户需要反复扫描预览图下方的文字才能比较“视觉类型、适用场景、状态”。

建议：在卡片顶部增加稳定的信息条：视觉标签、适用场景、密度（舒展/标准/高密度）；把版本与“内置/我的主题”降为辅助信息。选中态同时显示明确的“当前使用”文字，不只依赖勾选角标。

### P2：文章与图文的主题语言可以建立跨端对应关系

证据：文章主题和图文主题被分为两个独立入口，用户无法快速知道“暖纸杂志风”与“纸艺暖调”是否属于同一视觉家族。

影响：跨文章与图文生产时，品牌一致性需要靠记忆，主题选择成本变高。

建议：增加“视觉家族”概念，例如 Editorial、Terminal、Paper、High-impact；在文章和图文卡片上显示同一族标签，并提供“查看对应图文主题 / 查看对应文章主题”。

### P3：当前总览存在可利用的留白

证据：主题中心总览右侧留白较大，而“我的主题”列表纵向较长，用户需要滚动才能看到更多主题。

影响：首屏没有充分帮助用户建立主题地图，且主题管理列表的浏览效率偏低。

建议：在首屏右侧增加“最近使用 / 推荐组合 / 当前默认主题”的紧凑面板；我的主题改为双列或按状态分组，保持卡片高度一致。

## 建议优先级

1. P1：先为图文封面增加受控的下半部承载物，解决首屏大面积空白。
2. P1：增加图文页面骨架配方，让主题差异从换肤升级为构图差异。
3. P1：为文章增加舒展 / 标准 / 高密度阅读节奏档。
4. P2：预览增加首屏、中段、结尾的连续阅读锚点。
5. P2：再补充场景标签、视觉家族映射与主题卡信息层级。

## 可访问性与审查边界

- 截图可确认：主题入口、弹窗关闭、分类标签和选中状态都有可见表达。
- 截图无法确认：键盘焦点顺序、屏幕阅读器播报、真实对比度计算、长文本滚动和动态加载状态；这些仍应由自动化交互与对比度门禁覆盖。
- 当前审查使用本地工作台真实截图，不代表已完成完整无障碍合规审计。
