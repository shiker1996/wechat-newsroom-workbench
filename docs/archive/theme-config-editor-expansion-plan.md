# 主题可配置能力与编辑器扩展实施方案

> 状态：阶段 0–5 已完成  
> 制定日期：2026-08-01  
> 依赖：[文章排版与图文视觉主题 JSON 化方案](./article-and-social-theme-json-plan.md)阶段 0–6  
> 范围：用户文章主题、用户图文主题、主题中心实时预览、正式生产渲染与发布门禁

## 1. 目标

把当前仅开放颜色的主题编辑器升级为安全、可理解、可验证的完整主题工作室，使用户能够配置：

- 基础配色；
- 字体、字号与阅读节奏；
- 页面间距、圆角、边框和阴影；
- 文章与图文各自的受控组件配方；
- 图文纹理、装饰透明度和轻微倾斜等效果。

所有开放字段必须同时满足四条约束：实时预览生效、正式产物生效、服务端可校验、历史任务可追溯。不得出现“Schema 接受但生产渲染忽略”或“只在预览中有效”的配置。

## 2. 当前能力审计

### 2.1 已有数据契约

`themes/schema/theme.schema.json` 已定义四组基础 token：

| 分组 | 字段 |
| --- | --- |
| 颜色 | `background`、`surface`、可选 `page`、`text`、`muted`、`accent`、`accentSecondary`、`line`、`inverseText`、`codeBackground` |
| 字体 | `family`、`headingFamily`、`bodyPx`、`h1Px`、`h2Px`、`captionPx`、可选 `codePx`、`lineHeight`、`letterSpacingEm` |
| 间距 | `articlePaddingPx`、`sectionPx`、`paragraphPx`、`cardGapPx` |
| 形状 | `radiusPx`、`borderWidthPx`、`shadow` |

文章主题另有组件配方和行为字段，图文主题另有效果字段。所有配方值均由 `lib/themes/recipe-catalog.mjs` 白名单约束，不允许用户输入 CSS、选择器、HTML 或脚本。

### 2.2 当前 UI

`public/src/views/theme-manager.js` 只开放名称、描述与颜色。字体、间距、形状、组件配方和效果只能通过 JSON 导入修改。

### 2.3 当前渲染差异

- 图文编译器已消费全部颜色、圆角、边框、阴影及部分效果，配置链相对完整。
- 文章编译器目前只向排版管线传递部分颜色、字号、间距和图片圆角；`surface`、`accentSecondary`、`line`、`inverseText`、`codeBackground`、`h1Px`、`articlePaddingPx`、`cardGapPx`、`borderWidthPx`、`shadow` 等字段尚未形成完整生产映射。
- 因此不能直接把 Schema 中所有字段一次性暴露给 UI，必须先建立“配置字段—预览节点—生产节点”的覆盖矩阵。

## 3. 产品与交互方案

### 3.1 信息架构

主题编辑器采用四个折叠分组，默认只展开“基础配色”：

1. **基础配色**：背景、画布、内容表面、正文、弱化文字、主/次强调、边线、反白文字、代码背景。
2. **字体与节奏**：正文/标题字体角色、正文与标题字号、图注、行高、字间距、章节和段落间距。
3. **形状与质感**：页面内边距、卡片间距、圆角、边框宽度、阴影。
4. **组件样式**：按主题目标显示文章配方或图文配方；图文额外显示纹理、装饰透明度和倾斜角度。

高级项不与基础项混在同一色板网格中，避免用户面对 30 多个同权控件。

### 3.2 控件形式

| 数据类型 | 控件 | 交互要求 |
| --- | --- | --- |
| 颜色 | 色板 + 六位 HEX 文本 | 两者双向同步，显示对比度告警 |
| 字体角色 | 三项分段选择 | 无衬线、衬线、等宽，展示文字样本 |
| 有范围数值 | 滑杆 + 数值输入 | 滑杆快速试验，数字精确调整，单位常驻 |
| 枚举配方 | 带小样的选择卡 | 显示中文名称和作用部位，不暴露内部 ID 为主文案 |
| 布尔行为 | 开关 | 明确描述对正式文章的影响 |

所有输入在 `input` 时更新预览，在 `change` 时执行局部语义检查；不自动保存，继续由“保存并校验”统一持久化。

### 3.3 预览模式

实时预览增加目标切换：

- 文章：标题、导语、二级标题、正文、加粗、引用、列表、表格、代码、图片和图注。
- 图文：封面页、内容页、列表页、代码页和结尾页。

提供桌面内嵌预览和“手机宽度”两档；预览使用与正式生产相同的编译结果，不再维护一套手写 CSS 变量映射。用户修改字段后，只重编译当前主题和固定样稿。

预览旁显示“影响位置”：用户聚焦某个控件时，高亮所有使用该 token 或配方的样稿节点。例如调整 `line` 时同时高亮外框、信息卡、表格和代码框。

## 4. 技术方案

### 4.1 建立统一编译产物

为两个编译器统一输出以下结构：

```js
{
  themeRef: { id, version, hash, target },
  variables: { /* 规范化 token */ },
  recipes: { /* 已校验配方 */ },
  preview: { html, css },
  production: { inlineStyles | scopedCss },
  usageMap: { "tokens.colors.line": ["article", "blockquote", "pre"] }
}
```

- 文章正式产物继续使用公众号安全的元素级内联样式。
- 图文正式产物继续使用主题作用域内的 CSS 变量和受控类。
- `usageMap` 供前端高亮和测试使用，不参与正文内容生成。
- 预览必须从同一规范化主题和配方目录生成，不能单独解释字段。

### 4.2 补齐文章编译器

逐项补齐文章 token 的生产映射：

| 字段 | 正式作用位置 |
| --- | --- |
| `surface` | 引用、列表面板、表格或配方指定的内容表面 |
| `accentSecondary` | 次级标记、眉题辅助元素、列表符号 |
| `line` | 框线、表格、分隔符和代码边框 |
| `inverseText` | 反白标题、标签和深色强调块文字 |
| `codeBackground` | 行内代码和代码块背景 |
| `h1Px` | 一级标题 |
| `articlePaddingPx` | 文章根容器安全内边距 |
| `cardGapPx` | 卡片/列表配方内部间距 |
| `borderWidthPx` | 支持边框的配方，限制在门禁范围内 |
| `shadow` | 仅映射为预置且公众号兼容的阴影值 |

若某字段在某个配方中无作用，UI 显示“当前组件配方未使用”，不得假装生效。

### 4.3 配方元数据

把 `recipe-catalog.mjs` 从字符串数组升级为带元数据的只读目录：

```js
quote: [
  { id: "warm-card", label: "暖色卡片", previewRole: "blockquote" },
  { id: "dark-block", label: "深色反白", previewRole: "blockquote" }
]
```

运行时校验仍只保存 ID；中文标签、说明、适用节点和预览角色由目录提供。API 返回可编辑字段及其选项，前端不复制白名单。

### 4.4 主题编辑 API

保留现有草稿、校验和发布接口，扩展详情返回：

```json
{
  "editableSchema": {
    "groups": [],
    "recipeOptions": {},
    "ranges": {}
  },
  "draft": {},
  "validation": {
    "issues": [],
    "warnings": []
  }
}
```

增加 `POST /api/themes/preview`：只接受当前主题定义、目标和可选高亮字段，返回确定性预览；不保存草稿、不执行模型、不读取网络资源。请求体继续受 64KB 上限和 Schema 校验保护。已有用户主题也可通过 `POST /api/themes/:id/preview` 使用相同编译链路。

### 4.5 校验与发布门禁

发布前至少执行：

1. JSON Schema 和未知字段检查；
2. 枚举、范围与配方完整性检查；
3. 正文/背景、弱化文字/背景、反白文字/强调色、代码文字/代码背景的对比度检查；
4. 固定文章样稿的公众号 HTML 门禁；
5. 固定图文样稿的溢出和布局审计；
6. 编译覆盖检查：所有修改过的字段必须被目标编译器消费，或返回明确的“不适用”说明；
7. 主题版本与哈希快照生成。

错误阻止发布，警告允许用户确认后发布。不得在发布失败时静默使用默认主题。

## 5. 实施阶段

### 阶段 0：覆盖矩阵与基线冻结（1–2 人日）

实施状态：已完成（2026-08-01）。视觉清单位于 `docs/theme-style-capability-inventory.md`，机器可读覆盖契约位于 `test/fixtures/theme-style-coverage.json`，一致性门禁位于 `test/theme-style-coverage.test.mjs`。

- 逐个梳理现有 6 个文章主题和 14 个图文主题的视觉签名；正式清单见 [现有主题视觉能力清单与配置覆盖矩阵](./theme-style-capability-inventory.md)。
- 建立所有 token、文章配方、图文配方的消费矩阵。
- 为当前 6 个文章主题和 14 个图文主题保存结构基线及关键视觉截图。
- 标记当前“Schema 已支持但生产未消费”的字段。

验收：每个字段都有 `preview`、`article production`、`social production` 三列状态，后续阶段不能新增无归属字段。

### 阶段 1：统一编译契约并补齐文章映射（3–5 人日）

实施状态：已完成（2026-08-01）。文章与图文编译器现统一输出 `target`、`variables`、`recipes` 与 `usageMap`；文章端已补齐颜色、字阶、间距、圆角、边线和阴影的生产映射，图文端已补齐字阶、间距以及 `frame`、`ending`、`list`、`code` 等配方。新增生产消费测试，确保字段不只存在于 Schema，而会进入正式 HTML/CSS。

- 扩展 `article-theme-compiler.mjs`，消费计划开放的全部文章 token。
- 为两类编译器增加 `usageMap` 和统一的规范化输出。
- 保持现有主题视觉基线，差异必须有明确批准。

验收：文章主题中每个开放 token 改变时，正式 HTML 至少一个对应样稿节点发生确定性样式变化。

### 阶段 2：生产级固定样稿预览（2–4 人日）

实施状态：已完成（2026-08-01）。新增文章与图文生产级固定样稿及 `POST /api/themes/preview` 无保存编译接口；主题中心改为在隔离 iframe 中展示正式文章排版或正式故事板渲染结果，移除前端手写样式解释器。控件聚焦时通过 `highlightField` 标出对应生产节点，接口同时返回编译器 `usageMap`；相同定义重复编译保持确定性。

- 新增文章与图文固定样稿。
- 新增只编译、不保存的预览接口。
- 主题中心改用正式编译器输出，不再手写简化预览。
- 加入字段影响位置高亮。

验收：相同主题定义的预览与正式产物使用同一 token 和配方解释；重新加载后无预览漂移。

### 阶段 3：开放字体、间距与形状（2–3 人日）

实施状态：已完成（2026-08-01）。主题中心新增“字体与字阶”“间距节奏”“形状与层次”三个可折叠分组，开放 Schema 已有的 15 个字段；数值字段同时提供原生滑杆与精确输入，并共享范围、步长、单位和双向同步。字段输入先经浏览器本地边界校验，再进入阶段 2 的无保存正式预览；聚焦字段继续高亮生产影响位置。每组支持恢复到打开当前草稿时的值，窄屏自动收为单列。本阶段未提前开放文章或图文组件配方。

- 增加三个折叠分组及响应式布局。
- 增加滑杆、数字输入、字体角色和阴影控件。
- 增加本地实时校验、单位、范围和恢复当前主题值。

验收：键盘可操作；移动端不横向溢出；输入值、色值文本、实时预览和保存 JSON 四者一致。

### 阶段 4：开放文章与图文组件配方（3–5 人日）

实施状态：已完成（2026-08-02 更新）。统一配方目录已为全部文章与图文枚举增加中文名称、说明和固定样稿角色，并随用户主题详情下发，前端不维护第二份白名单。文章主题开放 10 组组件配方及对齐、重点色、章节编号行为；图文主题开放 8 组组件配方（新增独立封面标题），以及纹理、装饰透明度、内容倾斜效果。配置区明确限定为外观设置，不提供网格、内容顺序或故事板结构入口。每个配方值均通过 Schema 与正式固定样稿编译门禁，字段聚焦可高亮对应生产组件。

- 配方目录增加中文元数据和样稿角色。
- 文章与图文根据 `target` 展示不同配置。
- 图文开放纹理、装饰透明度和倾斜角度。
- 不允许主题修改网格、内容顺序或故事板结构。

验收：所有配方组合通过 Schema；高风险组合通过固定样稿溢出审计；未知配方稳定拒绝。

### 阶段 5：发布门禁、迁移与灰度（2–4 人日）

实施状态：已完成（2026-08-01）。新增统一发布审计器，保存校验与发布共用 Schema、对比度、编译覆盖、固定样稿 HTML 安全和布局结构五项门禁；失败问题包含字段、错误码与样稿节点，主题中心展示报告并定位首个控件。用户主题详情执行只读兼容检查：兼容草稿启用完整编辑器，旧结构草稿进入只读模式，只保留导出、历史版本和归档，不原地改写。发布仍创建不可变版本，文章与图文生产继续冻结主题版本和哈希快照；用户主题定义及历史版本随 SQLite 工作台备份接受结构、哈希与关联完整性校验。导入仍只创建草稿，必须通过新门禁后才能发布。

- 补齐对比度、HTML、布局和编译覆盖门禁。
- 对已有用户主题执行只读兼容检查，不原地改写历史版本。
- 新编辑器先对新草稿启用；旧主题打开时显示兼容报告。
- 更新导入导出文档、API 文档和备份验证。

验收：旧主题继续生成原有产物；新版本发布不会改变历史任务；失败能定位到具体字段和样稿节点。

预计总工作量：13–23 人日。建议阶段 0–2 作为第一批，先解决配置与生产渲染一致性，再开放更多控件。

## 6. 测试计划

### 6.1 单元与契约测试

- Schema 边界值、非法枚举、未知字段和颜色格式。
- 每个 token 的编译消费断言。
- 每个配方 ID 的确定性结构签名。
- 配方元数据与校验白名单一致性。
- 预览与生产编译结果的 token 等价性。

### 6.2 交互测试

- 色板、HEX、滑杆和数字输入双向同步。
- 切换文章/图文主题后只显示适用控件。
- 调整一个字段不会串改其他字段。
- 保存失败保留未保存输入并聚焦首个错误。
- 恢复历史版本创建新草稿，不修改旧版本。

### 6.3 视觉与生产测试

- 6 套文章主题固定样稿结构断言和关键节点样式断言。
- 14 套图文主题覆盖封面、正文、列表、代码和结尾页。
- 深色/浅色主题对比度。
- 微信内联 HTML 无非法标签、脚本和样式块。
- 375×667 图文页无内容溢出。

## 8. 不在本方案范围

- 用户输入任意 CSS、HTML、JavaScript 或外链字体。
- 主题修改文章内容、图文故事板、页面网格或内容顺序。
- 自动将文章主题转换为图文主题。
- 主题市场、多人审批和云同步。
- 在主题编辑器中调用模型自动生成主题。

## 9. 完成标准

- 主题中心可安全编辑 Schema 中计划开放的全部样式能力。
- 每个控件在实时预览和正式生产中都有一致、可测试的效果。
- 文章与图文共享 token 语义，但保留各自组件配方。
- 预览不再维护独立的简化样式解释器。
- 发布门禁能阻止不可读、溢出、非法或未被编译器消费的主题。
- 历史版本、任务快照和产物不受后续主题修改影响。
