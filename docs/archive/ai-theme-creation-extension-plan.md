# 主题中心 AI 创建主题扩展方案

> 状态：阶段 0–3 已完成  
> 制定日期：2026-08-01  
> 依赖：[文章与图文主题 JSON 方案](./article-and-social-theme-json-plan.md)、[主题配置编辑器扩展方案](./theme-config-editor-expansion-plan.md)  
> 范围：文章主题、图文主题、主题中心、模型服务、主题发布门禁

## 1. 决策与目标

主题中心新增“AI 创建主题”，不提供“空白创建”。现有“复制内置主题”和“导入 JSON”继续保留，分别服务于小幅改造和高级迁移。

AI 创建解决两个问题：

- 用户不需要理解全部 token、数值边界和组件配方，也能从视觉意图生成完整主题。
- 新主题不必依附某个内置主题的视觉语义，但仍严格落在现有 Schema 和配方白名单内。

AI 只创建用户主题草稿，不直接保存为已发布版本，不生成任意 CSS、HTML、脚本、选择器或新组件代码。生成结果必须进入现有实时预览、人工确认、校验和发布流程。

## 2. 产品边界

### 2.1 本期包含

- 通过自然语言创建一套完整文章主题或图文主题。
- 根据目标、视觉描述、适用内容和偏好生成主题名称、说明、标签、token、配方与行为配置。
- 在写入草稿前展示生成摘要、关键决策和警告。
- 将合法结果创建为新的用户主题草稿并打开现有编辑器。
- 对生成失败、字段越界、未知配方、对比度不足等问题执行确定性修复或给出字段级反馈。
- 记录所用模型、提示词版本、生成时间和结果摘要，便于审计，不保存模型的隐藏推理。

### 2.2 本期不包含

- 空白主题创建。
- AI 直接修改已发布版本；调整必须落到新草稿。
- AI 自动发布或绕过五项发布门禁。
- 生成任意 CSS、HTML、JavaScript、字体文件或远程素材。
- 由用户或模型新增配方类型、页面结构、图文网格与内容顺序。
- 根据单篇文章自动生成一次性主题；内容级主题推荐可作为后续扩展。

## 3. 入口与交互

### 3.1 主题中心入口

主题中心顶部的创建区调整为三个同级入口：

1. **AI 创建主题**：主入口。
2. **复制现有主题**：基于内置主题创建草稿。
3. **导入 JSON**：导入已有规范主题。

不显示“新建空白主题”。点击“AI 创建主题”打开创建面板，不离开主题中心。

### 3.2 创建面板

首屏只要求两个必填项：

- **主题类型**：文章 / 图文，单选且创建后不可切换。
- **想要的效果**：自然语言描述，建议 20–500 字。

可选的“补充偏好”折叠区包含：

- 使用场景：技术、职场、财经、新闻、生活方式或自定义描述。
- 明暗倾向：自动、浅色、深色。
- 视觉气质：克制、编辑感、活泼、硬朗、温暖、未来感等受控多选。
- 强调色：可选颜色，不填写则由 AI 决定。
- 阅读优先级：长文舒适、信息密度、视觉冲击三档。

系统同时展示提示：“AI 会在现有安全样式和组件配方内组合，不会生成任意网页代码。”

### 3.3 生成与确认

点击“生成主题”后：

1. 按钮进入明确的生成状态，防止重复提交；用户可以取消等待。
2. 服务端返回候选主题定义、生成摘要、警告和临时预览标识。
3. 右侧使用正式生产编译器展示固定样稿，未创建数据库草稿。
4. 左侧展示简短的设计说明与关键变化，例如配色、字阶、圆角、引用/代码配方。
5. 用户可选择“创建为草稿”“重新生成”或“修改描述”。

“创建为草稿”是唯一持久化动作。创建成功后进入现有主题编辑器，名称冲突由服务端生成稳定后缀并允许用户修改。

### 3.4 失败反馈

- 模型服务不可用：保留用户描述，提示检查“运行与配置”，允许重试。
- 结构化输出失败：服务端最多执行一次格式修复；仍失败则不创建草稿。
- 字段或配方非法：定位到具体字段，不把原始模型文本写入数据库。
- 对比度或布局门禁失败：候选仍可预览，但“创建为草稿”前应先执行受控自动修复；无法修复时返回具体问题。
- 用户取消：终止前端等待；若模型调用无法中断，返回结果也不得自动创建草稿。

## 4. AI 输入与输出契约

### 4.1 模型输入

模型只接收完成任务所需的数据：

- 用户填写的主题描述与偏好。
- `target`。
- 当前主题 Schema 的可生成字段、数值范围和枚举。
- 对应 target 的配方目录及中文说明。
- 少量设计原则与可访问性要求。

默认不发送文章正文、用户历史主题、工作区文件、密钥和模型服务配置。后续若增加参考主题，应只发送规范化主题定义，并明确展示给用户。

### 4.2 结构化输出

模型必须返回受约束的结构化对象：

```json
{
  "label": "主题名称",
  "description": "适用场景与视觉说明",
  "tags": ["editorial", "warm"],
  "tokens": {},
  "targetConfig": {},
  "designSummary": [
    { "title": "配色", "description": "暖纸底与低饱和棕色强调" }
  ]
}
```

服务端负责补齐并覆盖以下系统字段：`schemaVersion`、`id`、`version`、`targets`、`status=draft`、`source=user`、`basedOn=null`。模型不得决定 ID、状态、版本、所有者、发布时间或哈希。

`targetConfig` 在文章目标下只能映射为 `article`，在图文目标下只能映射为 `social`。不得同时生成两个 target。

### 4.3 确定性规范化

模型结果按以下顺序处理：

1. 严格解析结构化输出，拒绝附带代码块和额外顶层字段。
2. 合并系统字段并执行主题 Schema 校验。
3. 校验全部配方 ID 来自当前服务端配方目录。
4. 统一颜色为六位十六进制，数值按 Schema 边界和编辑器步进规范化。
5. 执行五项发布审计：Schema、对比度、编译覆盖、固定样稿 HTML 安全、布局结构。
6. 对可确定修复的问题执行一次本地修复，例如数值吸附、名称清理、颜色轻量调整；记录修复前后差异。
7. 使用正式编译器生成临时候选预览。

AI 输出不能成为新的主题解释器；最终主题仍由现有 validator、compiler 和 publish gate 决定。

## 5. 接口设计

### 5.1 生成候选

`POST /api/themes/ai/generate`

请求：

```json
{
  "target": "article",
  "prompt": "适合技术深度文章的深色终端主题，克制一些",
  "preferences": {
    "scene": "technology",
    "tone": ["restrained", "futuristic"],
    "brightness": "dark",
    "readingPriority": "long-form"
  }
}
```

响应：

```json
{
  "candidateId": "temporary-id",
  "definition": {},
  "designSummary": [],
  "repairs": [],
  "audit": { "valid": true, "checks": {}, "issues": [] },
  "preview": { "html": "...", "usageMap": {} },
  "model": { "serviceId": "...", "model": "..." }
}
```

约束：请求体限制 16KB；提示词限制 500 字；接口按工作区限流；候选只短期保存在服务端内存或带签名的短期缓存中，不进入主题目录。

### 5.2 创建草稿

`POST /api/themes/ai/candidates/:candidateId/create`

请求可包含用户最后确认的 `label` 和 `description`。服务端必须重新校验候选内容和候选有效期，而不是信任前端回传的完整定义。成功后复用现有用户主题服务创建草稿。

不应把“生成”和“创建”合并为一个接口，否则模型调用成功即产生垃圾草稿，也不利于用户比较和取消。

## 6. 模型服务与提示词

- 使用“运行与配置”中当前可用、支持结构化输出的文本模型服务。
- 若多个模型满足条件，默认使用模型中心标记的主题设计模型；没有专用标记时使用当前默认文本模型。
- 提示词作为版本化服务端模板维护，不写在前端。
- 温度保持中低档，优先保证 Schema 稳定；视觉变化通过明确的气质、配色与配方选择空间实现。
- 模型调用应设置独立超时、最大输出 token 和一次结构修复上限，不继承文章生成的长文本预算。
- 日志记录请求 ID、耗时、模型、提示词版本、校验结果和错误码；用户原始描述遵循现有工作区日志与隐私策略。

## 7. 安全与治理

- 模型生成内容视为不可信输入，必须经过与导入 JSON 相同或更严格的校验。
- 禁止模型生成 CSS、HTML、URL、字体地址、脚本与文件路径。
- 候选预览继续置于隔离 iframe，HTML 仅来自正式固定样稿编译器。
- AI 创建不具备发布权限；发布仍由用户操作并再次执行五项门禁。
- 候选和草稿需要记录 `creationMethod=ai`、模型服务、模型名和提示词模板版本，但密钥不得入库。
- 模型服务未配置、被禁用或健康检查失败时，入口仍可见但显示可操作的配置引导。

## 8. 数据与审计

建议在用户主题元数据或独立审计记录中增加：

```json
{
  "creationMethod": "ai",
  "aiProvenance": {
    "serviceId": "service-id",
    "model": "model-name",
    "promptVersion": "theme-create-v2",
    "generatedAt": "2026-08-01T00:00:00.000Z",
    "repairs": []
  }
}
```

不保存隐藏推理，不把用户密钥、完整服务配置或未选择候选写入主题版本。主题正式发布后，生产任务继续只冻结最终规范主题、版本与哈希，不依赖 AI provenance 重建产物。

## 9. 实施阶段

### 阶段 0：契约与基线（1–2 人日）

实施状态：已完成（2026-08-01）。已新增 `server/shared/themes/ai-theme-contract.mjs`，严格区分创建请求、模型候选与系统补齐后的主题定义；系统字段越权、未知字段、不安全文本、目标错误和一般输出错误均具有稳定错误码。文章与图文请求基线位于 `test/fixtures/ai-theme-contract-cases.json`，契约测试位于 `test/ai-theme-contract.test.mjs`。本阶段未接入模型、HTTP 路由、候选缓存或前端入口，不会创建数据库草稿。

- 定义 AI 主题候选 Schema、系统字段覆盖规则和错误码。
- 建立文章/图文各类描述样例及期望合法性基线。
- 确认模型选择、超时、预算、审计和候选过期策略。

验收：模型输出无法越权设置系统字段；非法字段和任意代码稳定拒绝；现有复制、导入、编辑和发布流程无回归。

### 阶段 1：服务端候选生成（2–4 人日）

实施状态：已完成（2026-08-01）。已新增版本化提示词与候选生成器 `server/shared/themes/ai-theme-generator.mjs`、带 TTL/容量控制的内存候选仓库及工作区限流器 `server/shared/themes/ai-theme-candidate-store.mjs`，并开放 `POST /api/themes/ai/generate`。生成链路关闭思考模式并请求 JSON 输出；首次 JSON 解析失败时只允许一次模型格式修复。候选随后执行颜色规范化、数值边界/步进吸附、必要的文字对比度修复，并记录每项差异，再经现有主题契约、五项发布审计和正式固定样稿编译。只有完整通过的结果才进入默认 15 分钟有效的内存仓库；取消、超时、限流、模型不可用或门禁失败均不会创建主题草稿。本阶段未实现候选确认落库和前端创建面板。

- 实现版本化提示词和结构化模型调用。
- 实现规范化、一次确定性修复、五项审计及正式预览编译。
- 实现短期候选存储、限流、取消语义与可观测性。

验收：固定测试提示中合法候选生成成功率达到约定阈值；所有候选均可被现有编译器解释；失败不创建数据库记录。

### 阶段 2：创建交互与草稿落库（2–3 人日）

实施状态：已完成（2026-08-01）。主题中心现以“AI 创建主题”为唯一全新创建主入口，复制与 JSON 导入保留在次级折叠区，不提供空白创建。创建面板支持文章/图文目标、20–500 字视觉描述、场景、明暗、阅读优先级及最多三项视觉气质；生成过程可取消，模型不可用、候选过期及创建失败均保留用户输入并提供就地恢复。候选区左侧展示设计摘要、确定性修复记录和可编辑的最终名称/描述，右侧展示正式生产编译样稿；重新生成不会创建数据库记录。新增 `POST /api/themes/ai/candidates/:candidateId/create`，只读取服务端短期候选并接受名称/描述，不接受前端主题定义；服务端重新执行发布审计、生成唯一用户主题 ID、创建草稿并立即消费候选。创建成功后进入现有完整主题编辑器，继续复用保存校验、发布、版本和归档生命周期。

- 增加 AI 创建面板、生成状态、设计摘要、警告和正式样稿预览。
- 增加重新生成、修改描述、创建为草稿和错误恢复。
- 创建成功后接入现有主题编辑器与草稿生命周期。

验收：用户可从一句描述完成“候选—确认—草稿—编辑—校验—发布”；未确认候选不进入主题列表。

### 阶段 3：质量优化（2–3 人日）

实施状态：已完成（2026-08-01）。新增 `server/shared/themes/ai-theme-quality.mjs`，从颜色、数值排版、字体/阴影枚举和组件配方四类信号计算同目标主题的视觉相似度，并同时比较全部内置主题与工作区用户主题。候选响应包含最近主题、相似度、`distinct/related/too-similar` 结论、是否建议重新生成，以及配色、字体字阶、形状层次和组件配方差异摘要；高于 94% 的候选明确提示可能过度复刻，但保留用户确认权。生成提示词现携带内置主题的紧凑视觉签名，并分别约束文章长文阅读和图文 375×667 画布的信息层级。主题中心以嵌入式原创性审阅记录展示比较结果；模型输出、Schema、配方、对比度或发布门禁问题按具体字段列出，用户描述和偏好在失败后保持不变并可直接重试。

生成提示词契约已升级为 `theme-create-v2`，逐键声明颜色、字体、间距、形状、行为与效果字段及枚举。服务端同时对高频模型偏差执行受控修复：`colors.border` 映射为 `line`、`colors.codeText` 映射为 `inverseText`；补齐缺失的字体角色、阴影和目标默认值；移除误放进文章 `behavior` 的 `readingPriority`、`codeTheme`、`brightness`；缺失或非法的行为值与组件配方回退到服务端白名单默认值。每项转换均进入候选修复记录，其他未知字段仍保持严格拒绝。

- 增加重复视觉检测与候选差异摘要。
- 调整提示词，使文章与图文在字阶、密度和配方选择上保持目标差异。
- 完善模型不可用、超时、格式修复和门禁失败的字段级反馈。

验收：文章与图文样例无明显同质化；可访问性问题在创建草稿前被修复或明确阻止；完整快速测试和构建通过。

预计总工作量：7–12 人日。

## 10. 测试策略

### 单元测试

- AI 输出 Schema、额外字段、系统字段覆盖和 target 隔离。
- 数值吸附、颜色规范化、配方白名单和名称清理。
- 一次修复前后差异以及不可修复错误。
- 候选过期、重复创建、取消和限流。

### 契约与集成测试

- 模型服务成功、超时、无结构化输出、截断和不可用。
- 生成接口不落库；确认接口只接受有效服务端候选。
- AI 草稿与复制/导入草稿使用相同的编辑、预览、校验、发布和版本流程。
- 文章与图文候选分别通过对应编译器和固定样稿审计。

### 交互测试

- 必填项、生成中状态、取消、重试和描述保留。
- 设计摘要与预览一致，重新生成不会误覆盖已创建草稿。
- 错误显示在相关输入或门禁字段附近，而不是只出现在预览区或 Toast。
- 键盘操作、焦点管理、窄屏布局和 `aria-live` 状态通知。

## 11. 完成标准

- 主题中心只有“AI 创建主题”这一种全新创建入口，不出现空白创建。
- AI 可生成文章或图文完整主题，但不能生成任意代码或新增组件配方。
- 生成候选在用户确认前不落库，确认后只创建草稿。
- 所有 AI 草稿复用现有编辑器、正式预览、五项门禁、版本和发布链路。
- 模型不可用或输出非法时不产生半成品主题，并向用户提供可恢复的反馈。
- 已发布主题和历史生产任务仍由不可变版本与哈希决定，不依赖模型重放。
