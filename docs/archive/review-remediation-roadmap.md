# Review 整改事项归并与实施路线

> 状态：待实施  
> 日期：2026-08-14  
> 来源：`review-PTC.md`、`review-creative.md`、`review-simple.md`、`review-standard.md`  
> 目的：合并重复发现，剔除已解决事项，将剩余问题整理为可验收的实施批次。

## 1. 总体结论

四份审查报告覆盖安全、HTTP、持久化、LLM 流水线、主题、插件、前端和工程治理。报告之间存在大量重复编号，部分结论也已被通用 Conversation ToolCall Agent 改造解决。

剩余事项建议按六个批次推进：

1. 本地服务安全边界与 Markdown XSS；
2. 确定性生产故障、路径和乱码；
3. 数据库迁移、事务与长期运行；
4. LLM 预算、重试、评分与内容门禁；
5. 主题、插件信任链与公共模块收敛；
6. 文档、发布和经人工确认的磁盘清理。

## 2. 已解决或不再执行的事项

以下旧问题已由 Conversation ToolCall Agent Phase 0–5 及后续清理解决，不再进入整改计划：

- 自定义图文对话硬编码 `webSearch:true`；
- 编辑室 `fetchEvents` 私有协议；
- `autoFetchEditorialEvents` 服务端专用编排；
- `runEditorialTurnStream`、`runTutorialChatStream`、`runCustomSocialChatStream` 三个旧执行器；
- 三入口 feature flag 双链回退；
- 三入口重复工具卡协议；
- 自主写作私有 NDJSON 事件消费逻辑；
- Agent run 与工具执行缺少关联审计；
- Agent 执行历史缺少界面；
- 对话阶段资料无法被创建阶段复用；
- 本地项目绝对路径直接注入模型上下文。

旧审查文档作为历史证据保留，不直接按其中的编号逐条施工。

## 3. Phase R1：本地服务安全边界与 Markdown XSS

优先级：P0。

### R1.1 本地 API 请求边界

- 增加 Host 白名单，仅接受应用声明的本机 Host；
- 增加 Origin 校验，拒绝未授权网页跨源调用；
- 创建会话级随机 CSRF token；
- 用一次性或会话绑定确认替换以下固定字符串：
  - `TRUSTED-LOCAL-PLUGIN`；
  - `RESTORE`；
  - `DELETE-BATCH`；
- 敏感操作增加二次确认：本地项目读取、备份恢复、插件安装/回滚/卸载、系统配置修改；
- 生产错误响应只返回稳定错误码，内部路径、SQLite 和文件系统错误写服务端日志。

验收：恶意网页不能通过简单请求调用写接口；伪造固定请求头不再获得管理权限；错误响应不包含绝对路径和内部异常正文。

### R1.2 本地项目读取授权

- 为项目读取建立用户授权根目录；
- 对自动检测出的绝对路径执行同样的根目录检查；
- 读取授权绑定当前会话和当前请求；
- 保持符号链接、秘密文件名和绝对路径脱敏门禁。

验收：未授权目录、父目录、秘密文件和符号链接目标均不能被读取或注入模型。

### R1.3 Markdown 与预览安全

- Markdown 注释只允许完整闭合的结构化占位，禁止整行原样进入 HTML；
- 链接与图片 URL 建立协议白名单；
- 调整代码跨度与链接替换顺序，反引号中的 Markdown 不得生成活动链接；
- 公众号预览与产物预览 iframe 增加 `sandbox`；
- 为预览内容配置最小 CSP。

验收：注释拼接标签、`javascript:`、危险 `data:` 和代码跨度中的伪链接均不能形成可执行内容；预览不能访问父页面脚本上下文。

### R1.4 SSRF、路径与插件信任

- 收敛统一 IP/URL 校验实现，覆盖 IPv4、IPv6、6to4、回环和私网；
- Firecrawl、CDP、RSSHub 和远程工具使用同一边界；
- 降低 DNS rebinding/解析后切换目标的 TOCTOU 风险；
- `serveStatic` 使用 `path.relative` 判断目录边界；
- 插件回滚版本参数使用白名单并验证必须来自版本目录；
- 远程工具和采集插件执行管理操作时使用同一管理员校验；
- 明确第三方插件“安装即信任本机代码”的边界，并评估 worker/子进程隔离。

验收：私网、回环、越界路径和未登记版本无法进入网络、静态文件或插件执行路径。

### R1.5 凭据治理

- 轮换审查报告确认存在于本地秘密文件中的全部凭据；
- 迁移到系统环境变量或系统密钥链；
- 限制秘密存储文件 ACL；
- 秘密扫描覆盖已知未跟踪秘密位置，但不得输出秘密正文；
- 插件运行上下文只注入声明过的凭据引用。

验收：仓库和普通本地文件中不保存可直接使用的长期密钥；未声明插件无法读取其他扩展的凭据。

### R1 限制性实施记录（2026-08-14）

已落地的代码侧边界：回环 Host/Origin 校验、随机 CSRF、一次性敏感操作确认令牌、本地项目读取单次授权、稳定 5xx 响应、Markdown URL/注释/代码跨度防护、预览 iframe sandbox、统一 CSP、安全静态路径判断、IPv4/IPv6/6to4 私网判断，以及工具插件回滚版本白名单。固定确认字符串已从生产代码与测试中移除。

本轮按“限制性 R1”不自动执行外部凭据轮换，也不擅自迁移用户现有密钥。上线或继续接入真实服务前，仍须由密钥所有者完成旧凭据吊销、新凭据签发与系统密钥链迁移；完成后再执行不输出秘密正文的定向扫描验收。DNS rebinding 的连接级地址固定、第三方本机代码进程隔离属于后续纵深防御，不作为本轮启用本地工作台的阻断项。

## 4. Phase R2：确定性生产故障、路径与乱码

优先级：P0–P1。

### R2.1 三个确定性故障

- 备份 manifest 使用 `APP_VERSION`，恢复时校验 schema/app 兼容性；
- 恢复 `GET /api/system/settings`，返回运行配置读取结果；
- Reddit Chrome 启停脚本路径改为真实的 `plugins/reddit/scripts/`，并补路由测试。

验收：备份显示当前应用版本；系统页和编辑器能读取运行配置；Reddit 启停、停止和重启均调用存在的脚本。

### R2.2 HTTP 与文件流健壮性

- NDJSON 路由监听 response 错误和客户端断开；
- 客户端断开后中止 Agent、模型和工具调用；
- catch 中写流前检查 `destroyed/writableEnded`；
- `createReadStream().pipe()` 统一增加 source/response 错误处理；
- 文件存在性和打开操作合并到同一 try 范围，降低 TOCTOU；
- 查询参数 limit 统一限制范围并处理 NaN；
- 请求体使用流式 UTF-8 解码，避免多字节字符跨 chunk 损坏。

验收：客户端中断、文件消失、非法 limit 和中文分块请求不会导致进程崩溃或正文损坏。

### R2.3 路径、文案和编码

- 修复 `article-routes.mjs` 中损坏的 404 文案；
- 修复 GitHub client、Mermaid、ECharts 和 URL fetch 脚本中的乱码；
- 删除或合并重复且乱码的抓取脚本；
- 建立 UTF-8/可疑乱码 CI 门禁；
- 修复过时的源码路径注释。

验收：生产代码和用户可见错误中不存在已知乱码模式或 `?????` 占位。

### R2 实施记录（2026-08-14）

已完成：备份清单使用 `APP_VERSION` 并校验 schema/应用版本兼容性；恢复设置读取接口；修正 Reddit Chrome 脚本路径；请求体改为流式 UTF-8 解码；NDJSON 在客户端断开或响应错误后停止写入并发出中止信号；静态文件与各产物流统一监听读取错误和响应关闭；查询 `limit` 统一回退与封顶；修复文章 404、GitHub client、Mermaid、ECharts 与 URL fetch 脚本的已知乱码，并增加关键生产文件乱码回归门禁。

Agent、模型及工具内部对 AbortSignal 的逐层强制取消继续归入 R3/R4 生命周期收敛；本阶段已确保 HTTP 层不再向断开的连接写数据。

## 5. Phase R3：数据库、事务与长期运行

优先级：P1。

### R3.1 迁移版本化

- 引入显式 schema version；
- 破坏性数据修复只执行一次；
- 移除每次启动执行的 archived、`research_eligible` 和旧 pool role 数据改写；
- 表重建使用事务；
- 修复旧库 candidates 重建时的外键级联和字段丢失风险；
- 为 `theme_usage` 增加外键或确定性清理策略。

验收：重复启动不会修改用户业务数据；模拟迁移中断不会留下半张表；旧库升级保留候选及关联数据。

### R3.2 多语句写事务

- 文档保存、版本插入、历史裁剪进入一个事务；
- 图文评分和候选轨道更新进入一个事务；
- 中断任务恢复进入一个事务；
- 批次删除明确数据库和文件系统的失败补偿顺序；
- 备份恢复期间暂停其他写请求和后台任务。

验收：在每个语句边界注入失败后，不出现缺版本、半更新、幽灵批次或恢复期间的并发覆盖。

### R3.3 SQLite 生命周期

- 配置 `busy_timeout`；
- 增加退出关闭钩子；
- 关闭前 checkpoint WAL；
- 恢复流程避免独立连接与主连接竞争；
- 防止第二实例误把第一实例运行中的任务标记为 interrupted。

验收：并发读写和正常退出不遗留不可恢复的 WAL 状态；双实例行为明确且可检测。

### R3.4 ID、唯一性、排序与统计

- 候选编号改用不因删除而碰撞的生成方式，并检查数据库 changes；
- 批次随机 ID 增加冲突重试；
- 修复批次级文档 `candidate_row_id=NULL` 时 UNIQUE 失效；
- 最新热点在 SQL 中按发布时间排序后截取；
- 工件归属优先按 batch ID，日期回退仅用于无歧义场景；
- 批次共享目录判断不依赖固定 1000 条上限；
- 统一采集状态为 `success/failed/interrupted`；
- 报表按业务时区或批次业务日期聚合。

验收：删除后重建、同日多批次、批次级文档和 UTC+8 月/周边界均有回归测试。

### R3.5 任务与外部进程生命周期

- 终态任务从进程内 Map 清理，仅保留持久化记录；
- CDP 请求增加超时和 Chrome 崩溃恢复；
- worker 失败路径保证 finally 执行；
- PowerShell/RSSHub 超时结束完整进程树；
- Chrome profile 增加互斥锁；
- Tavily、截图、远程 execute 统一使用 AbortSignal 超时。

验收：长时间运行任务 Map 有上限；失败任务不遗留 Chrome、Node、PowerShell 或 RSSHub 子进程。

## 6. Phase R4：LLM 预算、重试、评分与门禁

优先级：P1–P2。

### R4.1 输出预算

- 明确 caller `maxOutputTokens` 与 purpose profile 的优先级；
- 删除无效上限参数或让显式上限覆盖 profile；
- thinking reserve 只对声明支持 thinking toggle 的 provider 生效；
- 预算决策进入模型调用审计。

验收：单测覆盖 profile、显式 cap、thinking reserve 和 provider 能力组合；审计记录能解释最终预算来源。

### R4.2 重试语义

- 流式与非流式 thinking 空内容使用同一错误分类；
- `streamComplete` 补齐截断和 adaptive retry；
- 429/5xx 使用有限指数退避；
- 重试必须受总时间、总调用次数和取消信号约束。

验收：同一模型故障不因是否注册流式 sink 而表现不同；客户端取消后不继续重试。

### R4.3 评分与内容门禁

- 修复 `audienceRelevance || 12` 的零值问题；
- 修复有序列表被误判为脚注；
- breaking 评分量纲检测不依赖理由数量；
- NaN 字数配置必须显式拒绝；
- 统一文章、教程和早报的字数门禁语义；
- 去掉早报硬编码 1800；
- 图文布局审计失败不得复用旧报告作为本轮通过；
- 脑暴单卡失败记录并继续处理剩余卡片。

验收：0 分、无引用有序列表、非法长度配置、布局审计失败和单卡异常均有回归测试。

### R4.4 Prompt 注入和上下文

- 对文章、抓取正文和模型中间产物使用统一数据定界；
- 注明嵌入内容是不可信数据；
- 截断发生在段落或代码围栏边界并附截断标记；
- 模型内容写入 Markdown 工件前转义标题、围栏和表格控制符；
- 编辑会、自主写作和自定义图文统一限制消息数与总字符/token；
- 账号上下文不永久绑定 `process.cwd()`，配置更新可刷新。

验收：正文中的指令不能改变系统任务；超长会话可继续运行；生成的 Markdown 结构不被模型文本破坏。

### R4.5 JSON 解析统一

建立共享解析模块，统一：

- Markdown 围栏剥离；
- JSON 主对象定位；
- length 截断分类；
- 一次结构修复；
- `invalid_output` 审计；
- 稳定、脱敏的错误码。

验收：各流水线对相同异常输出产生相同结果，不重复消耗多轮模型调用。

## 7. Phase R5：主题、插件与公共模块收敛

优先级：P2。

### R5.1 主题契约

- `article.behavior`、`social.effects` 在 Schema、运行时校验和编译器中保持一致；
- 编译器为缺失字段提供防御性默认；
- 图文对比度按配方真实背景计算；
- 半透明背景进入 computed-style 或等价实测门禁；
- `codePx` 要么被正式消费，要么从契约删除；
- 决定 JSON Schema 是否在运行时真正执行；
- 用户导入主题执行数值步进校验。

验收：缺字段、强调色背景、半透明背景和非步进数值不能绕过发布门禁或产生 NaN CSS。

### R5.2 扩展信任与迁移

- 工具、远程工具和采集插件使用一致的管理员与权限策略；
- 安装包增加来源、签名或校验和信任链；
- legacy 配置迁移在跳过前输出字段 diff；
- 空字符串和已配置空值语义明确；
- config hash 纳入秘密值摘要；
- 为 legacy fallback 设定下线版本。

验收：来源不可信、签名不匹配或声明权限不完整的扩展不能启用；迁移不静默丢字段。

### R5.3 公共实现收敛

优先抽取：

- 原子 `writeUtf8`；
- HTTP JSON/错误响应；
- URL/IP/SSRF 校验；
- JSON 提取与解析；
- 颜色对比度和混色；
- `escapeHtml`；
- `fontStack`；
- clamp 和数值范围；
- RSS 解析；
- PowerShell 生命周期管理。

验收：每类能力只有一个生产实现和一套边界测试；调用方不再复制安全敏感逻辑。

### R5.4 大文件拆分

按领域拆分：

- `system-routes.mjs`；
- `server.mjs` 路由上下文；
- 大型 LLM pipeline；
- 大型前端 view；
- 主题管理模块。

拆分优先级由安全敏感度和变更频率决定，不以行数作为唯一标准。

### R6.2 磁盘清理

以下删除必须先人工确认登录态、恢复价值和备份状态：

## 9. 建议排期与依赖

| 批次 | 建议周期 | 前置依赖 | 主要风险 |
|---|---:|---|---|
| R1 安全边界 | 1–2 周 | 无 | 可能影响所有 API 调用和预览 |
| R2 确定性故障 | 2–4 天 | 可与 R1 部分并行 | 路由与脚本兼容 |
| R3 数据完整性 | 1–2 周 | 完整备份与迁移样本 | 旧库升级与删除补偿 |
| R4 LLM 正确性 | 1–2 周 | 预算与错误码决策 | 成本、行为和文章产物变化 |
| R5 架构收敛 | 2–3 周 | R1/R4 稳定接口 | 大范围重构回归 |
| R6 工程清理 | 2–5 天 | 前述批次完成 | 磁盘删除需人工确认 |

R1 与 R2 可拆成多个小 PR；R3 的迁移改造应独立发布；R5 不应与安全修复混在同一变更中。

## 10. 统一完成定义

整改计划只有同时满足以下条件才算完成：

1. 所有 P0 安全边界都有自动化回归；
2. 迁移、恢复和多语句写均通过故障注入测试；
3. 流式与非流式模型调用具有一致的预算、取消和重试语义；
