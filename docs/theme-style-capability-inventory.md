## 1. 目的

本清单回答三个问题：

1. 现有主题实际上有哪些视觉能力；
2. JSON 中声明的字段是否被实时预览和正式生产消费；
3. 哪些能力可以直接开放，哪些必须先补齐编译器。

状态定义：

- **完整**：字段直接决定正式产物，并覆盖预期节点；
- **部分**：仅某些配方、枚举值或节点使用；
- **未消费**：Schema 接受且主题文件有值，但正式编译器未读取；
- **不适用**：该目标不使用此字段。

## 7. 阶段 1–4 的开放判定

### 可以保留在当前 UI

- 全部颜色控件；但文章的内容表面、次强调、边线、反白文字和代码背景在阶段 1 完成前，应显示“预览可调，正式文章待补齐”的兼容提示。

### 阶段 1 必须先完善

- 文章颜色缺失映射和硬编码色；
- 文章 `h1Px`、字间距、页面内边距、卡片间距、边框和阴影；
- 图文字体字号与全部间距；
- 图文 `frame`、`ending`、`list`、`code` 配方；
- 图文标题字体角色和倾斜角度的确定性语义。

### 阶段 3 可开放

- 已通过生产消费测试的字体、字号、行高、字间距、间距、圆角、边框和阴影。

### 阶段 4 可开放

- 已具备中文元数据、固定样稿、布局审计和生产消费测试的文章/图文配方与效果。

## 8. 阶段 0 完成标准

- 20 个主题均在本清单中有唯一记录；
- Schema 中每个 token、配方和效果字段均有生产消费状态；
- 机器可读契约位于 `test/fixtures/theme-style-coverage.json`；
- 自动化测试确保主题增删、Schema 字段和配方目录变更时必须同步更新覆盖清单；
- 后续 UI 不得开放状态为“未消费”的字段。
