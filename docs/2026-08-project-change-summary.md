# 2026 年 8 月项目变动整理

> 统计范围：2026-07-30 至 2026-08-30；Git 基线为 `0.1.0`（2026-07-29）。
> 当前工作区干净，HEAD 为 `0e50ca7`；`package.json` 当前版本为 `0.7.1`。

## 一句话结论

过去一个月，「见字」从一个能跑通公众号内容生产流程的本地工具，快速演进成一套“采集—研判—选题—成稿—排版—视觉交付”闭环的内容生产工作台。最明显的变化有两条：一是把 AI 能力和工具能力逐步平台化、可治理化；二是把社交卡片和封面图从“能生成”推进到“可审计、可修复、可交付”。

## 可验证的整体量级

- 从 `0.1.0` 到当前 HEAD：202 条提交，含 193 条非合并提交。
- 变更涉及 1,275 个文件，约新增 94,353 行、删除 10,519 行。
- 版本推进：0.2.0、0.2.2、0.3.0、0.4.0–0.4.3、0.5.0–0.5.1、0.6.3、0.6.8，并在 8 月 29 日准备 0.7.0 / 0.7.1。
- 当前 README 将产品定位为本地优先的公众号编辑工作台，覆盖信息采集、事件研判、编辑决策、文章生产、视觉交付、独立创作和扩展运维。

## 变动时间线

### 7 月 30 日—31 日：先把“工具”变成可扩展的工作台

- 完成技能与工具页面拆分，为后续能力路由和扩展管理留出结构。
- 完成开源前置收尾：MIT 许可证、贡献指南、行为准则、安全文档、Dependabot、Issue / PR 模板、CI 与秘密扫描等。
- 增加 Tavily 网络 / 新闻搜索和本地文档目录检索，并把自主写作、自定义图文接入搜索槽位。
- 搜索从创作表单里的手动开关，调整为由统一的信息工具槽位管理。

可引用的判断：这一阶段解决的不是某个页面功能，而是“信息从哪里来、工具如何接入、项目如何对外分发”的基础问题。

### 8 月 1 日—2 日：主题、检索和视觉基础设施成形

- 文章排版与社交图文主题 JSON 化，增加主题编辑器、能力覆盖率校验、发布门禁和生产预览。
- 主题中心支持 AI 创建主题；视觉规则从编译器硬编码逐步迁移为主题配置。
- 社交卡片增加故事板密度预算、稀疏页兜底、布局失败定位和封面标题语义断行。
- 编辑室改为先抓取候选来源原文，再进入对话；增加本地段落检索，长正文不再简单截断。
- 增加首次安装引导、RSSHub 自动准备、配图占位与 timeline / datacard 确定性生成。

可引用的判断：AI 负责提出内容或视觉方案，系统负责契约校验、确定性渲染和失败兜底，开始成为项目的基本设计方式。

### 8 月 3 日—8 日：从“生成内容”推进到“可控生产”

- LLM 网关接入 reasoning content、推理强度、usage 与 reasoning token 记录；针对超时、空内容、内容过滤、输出预算耗尽增加诊断和重试。
- AI 后台任务支持候选级并行、批次级互斥、FIFO 队列和 `queued` 状态。
- 新增公众号文章封面图：AI 只做排版决策，系统通过规格校验和确定性模板渲染输出 900×383 PNG。
- 封面主题从 5 套扩充到 10 套，支持早报封面、封面主题选择和 AI 生成封面主题。
- 完成一次 73 项前端交互、布局、可访问性和安全问题专项收尾；统一正文 H1 与文档 / 封面标题口径。
- 文章长度门禁统一为配置项，并从强阻断调整为建议性告警。

可引用的判断：这一周的重点不是“让模型多生成一点”，而是让模型输出进入任务队列、预算、审计、重试和确定性产物链。

### 8 月 9 日—16 日：架构重构与失败恢复进入主线

- 持久化层拆成迁移、查询服务和领域 Repository；批次、候选、任务、文章排版和社交卡片路由逐步模块化。
- 采集能力转入统一 Collector / Manifest / Runner 体系，扩展配置、能力路由和工具运行时统一。
- 新增失败对象索引：采集源、热点打标、事件卡可以按对象重试；支持跳过、恢复和失败原因分类。
- 编辑室、自主写作、自定义图文统一 ToolCall Agent 协议、能力授权、执行预算、事件流和审计关联。
- 完成能力接入治理、消费者—能力基线、插件边界和文档重组。

可引用的判断：项目开始把“失败怎么办”当成产品能力，而不是异常日志；同时，扩展系统从“能插入”转向“能声明、能审计、能判断兼容性”。

### 8 月 17 日—19 日：配置与信息源管理收口

- 模型配置支持设置默认供应商，并统一配置编辑器与 `defaultProvider` 联动。
- AI 辅助来源管理、内容支柱驱动的仓库发现和采集源状态保留策略陆续落地。
- 沉浸式侧边栏、思考流展示、模型调用详情、前端可访问性和交互细节继续完善。

### 8 月 22 日—30 日：社交卡片成为新的主战场

- 完成页面专属组件生成链路，重构故事板内容规划、组件装箱和布局修复流程。
- 内容页统一使用自适应容器；布局修复按阶段执行，失败信息定位到具体页面。
- 从仅看结构规则，升级为浏览器真实布局审计，并增加文字可见性硬门禁。
- 事件热榜接入图文池；热点研判和四层选题评分完成改造，内容分流、读者利益和候选池位贯穿后续编辑流程。
- AI 视觉生成流水线拆分为 CSS 生成、页面生成、布局审计、修复和截图阶段，与程序化视觉链路共享发布文案生成。
- 8 月 29 日准备 0.7.0 / 0.7.1；8 月 30 日继续修复默认字号、样式缺失、产物预览和会话唯一 ID 等收尾问题。

可引用的判断：社交卡片的核心问题已经从“模型能不能写出卡片”变成“内容、布局、主题、截图和发布文案能不能稳定交付”。

### 推荐文章结构

1. **开头：先给读者看变化幅度**——一个月、202 条提交、版本从 0.1.x 推进到 0.7.1，重点不是数字本身，而是产品边界发生了变化。
2. **第一部分：输入端**——网络搜索、本地知识库、来源原文抓取、AI 兴趣仓库发现，让选题不再只依赖单一热榜。
3. **第二部分：决策和写作端**——事件聚类、四层评分、编辑会、作者实践门禁、文章流水线和可配置技能。
4. **第三部分：输出端**——封面图、主题系统、配图生成、社交卡片，以及从 AI 方案到确定性渲染的分工。
5. **第四部分：工程化底座**——任务并发、失败对象重试、能力治理、插件 Manifest、审计与兼容政策。
6. **结尾：下一阶段问题**——当系统已经能稳定地产出内容和视觉物料，重点会转向质量评估、真实使用反馈、发布闭环和跨平台支持。

## 写作时需要谨慎的地方

- `0.7.0` / `0.7.1` 目前是 release prepare 提交和 CHANGELOG 记录；不要直接写成“已正式发布”，除非另有发布页或 tag 证据。
- “支持 macOS / Linux”不能作为当前能力宣传。README 明确写的是 Windows 10/11 完整验证，其他平台尚未作为受支持平台验收。
- “AI 自动写完并保证正确”不符合项目当前边界。项目文档明确保留作者对观点、来源、版权和发布风险的确认责任。
- “浏览器审计保证所有视觉问题消失”也不准确。它是交付门禁和修复机制，不等于内容质量或所有设备上的视觉效果都被证明。
