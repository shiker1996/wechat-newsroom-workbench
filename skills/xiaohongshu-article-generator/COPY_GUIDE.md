# 小红书文案写作规范 v3.0

**适用范围**：小红书工具种草贴图文案，模式 A（工具推荐风）。

## 整体风格

### 1. 去公文感，强种草语气
- 替换冰冷的技术参数式文案，改为程序员友好的口语化、轻量化表达，杜绝技术报告式文风
- 高频加入平台爆款软语气词（"谁懂啊"、"封神"、"闭眼冲"、"直接抄作业"），贴合平台流量逻辑，大幅降低技术门槛
- 融入程序员圈内梗，打造接地气人设，拒绝生硬冰冷的专业表述

### 2. 视觉清爽，重点突出
- 用 emoji + 短句标题划分板块，拒绝长标题、大段文字
- 板块间用空行 + 简约分割线分层，告别密密麻麻的罗列，完美适配手机竖屏阅读
- 单段文字控制在 2-3 行，避免视觉疲劳

---

## 内容润色

### 1. 放大核心优势，数据暴击
- 重点突出真实对比数据（慢 245 倍、内存多 14 倍、13.9x 差距），杜绝"好用、高效"等模糊夸赞
- 把枯燥参数转化为直观差距，强化视觉冲击力，让用户一眼感知价值

### 2. 技术功能通俗化，场景化
- 专业术语直接转化为程序员日常痛点解决方案，不讲原理只讲使用体验
- 示例：类人记忆系统 → 告别反复手动调参，自带智能记忆超省心；多智能体协作 → 复杂需求并行处理，加班时间直接减半

### 3. 带情绪态度，拒绝平淡
- 加入真实使用感叹、个人测评感受（"这数据我自己看都觉得离谱"、"稳如老狗"、"再也不用低效加班"）
- 让文案有情绪、有性格，提升用户共鸣与记忆点

## 爆款黄金结构

核心逻辑：情绪留人 → 结果洗脑 → 干货留存

1. **痛点情绪钩子**（开篇必爆）：直击程序员高频痛点 + 爆款感叹，3 秒抓住眼球
2. **炸裂结果前置**：直接甩核心效果、数据优势，先给用户福利
3. **痛点对应卖点**：只选 3-4 个最强卖点，每个卖点绑定对应解决的痛点
4. **实测体感反馈**：直白描述上手使用感受，强化真实可信度
5. **极简一键教程**：多系统操作步骤清晰区分，指令可直接复制
6. **适用人群 + 避雷**：明确适配人群，小范围避坑
7. **收尾 CTA 引导**：开源协议 + Star / 关注引导

## 通用规范

### 格式规范
- 文案纯文本输出，不使用 Markdown 加粗、表格、分割线等语法
- emoji 可以保留
- 用自然段落组织内容，层次靠空行区分，不靠语法符号
- 文案中**不能暴露分页结构**（P1/P2/P3），用空行分割板块

### 标签规范
- 末尾 6-8 个 #标签，用空格分隔
- 遵循「精准垂直词 + 技术词 + 热门种草词」组合

### 常用错误
| 错误 | 修正 |
|------|------|
| "该产品支持 X 功能" | "用它搞定 X，超方便" |
| 罗列所有功能点 | 只选 3-4 个最强卖点 |
| 结尾无引导 | 必须有直白 CTA |
| 文案中暴露分页结构 | 用空行分割板块 |
| 开篇铺垫过多 | 直接痛点 + 结果 |
