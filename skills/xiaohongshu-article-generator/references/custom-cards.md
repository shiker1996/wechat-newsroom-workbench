# 自定义图文规范（教程 / 清单 / 观点，公众号与小红书渠道）

## 目标

把作者提供的主题、要点和素材转成可保存、可搜索的图文卡片，不依赖 GitHub 仓库事实。首批开放三种内容类型：教程、清单、观点。种草、生活类因广告与功效表述边界复杂，暂不开放。

## 体验真实性三来源等级（硬约束）

事实基座中每条核心要点都带有 `source_level`，文案与故事板必须遵守：

| 来源等级 | 含义 | 允许的表达 |
|---|---|---|
| `author_experience` | 作者真实体验 | 可以写成第一人称亲历（"我用过""我的做法是"） |
| `user_material` | 用户提供素材 | 必须保留来源归属（"据××报道""官方文档显示"） |
| `model_suggestion` | 模型建议 | 只能写成建议或参考（"可以试试""一种思路是"），禁止写成亲测、效果、收益或数据 |

任何页面都不得把 `model_suggestion` 包装成作者亲历；`model_suggestion` 要点不得单独成页充当卖点。

## 内容类型故事线

| 类型 | 推荐页面结构 | 必须避免 |
|---|---|---|
| 教程 tutorial | 封面 → 场景与痛点 → step 分步页（每页 1–2 步）→ 注意事项（boundary）→ 结尾 | 跳过前置条件、把建议写成作者验证过的步骤 |
| 清单 list | 封面 → 筛选标准 → item 条目页（每页 2–4 条）→ 边界（boundary）→ 结尾 | "闭眼入""全都好用"式无边界推荐 |
| 观点 opinion | 封面 → 核心论点 → highlight 论据页 → 反方与边界（boundary）→ 结尾 | 把个人判断写成行业共识或数据结论 |

正常 4–10 页。素材不足时删页，不凑页数；至少保留一页 boundary 说明事实边界与限制。

## 渠道差异

| 维度 | 公众号（wechat-custom-cards） | 小红书（xiaohongshu-custom-cards） |
|---|---|---|
| 页型 | 375×667（9:16） | 375×667（9:16），与公众号一致 |
| 品牌行 | `CUSTOM / 内容类型` | `小红书 · 内容类型` |
| 页脚 | 来源等级与体验边界说明 | 同左，可追加话题标签 |
| 文案 | 短句分块、自然承接 | 更强的首图钩子、emoji、末尾 6–8 个话题标签 |

小红书可使用数据卡、对比卡、步骤卡、时间卡、场景卡、亮点卡等版式块（见 DESIGN_SYSTEM.md）；布局审计报告 underfilled/overfilled 时优先增减内容，不缩放字号。

## 标题与文案

- 标题不超过 20 字，包含具体场景或对象；教程优先"几步搞定什么"，清单优先"N 个什么"，观点优先"一个反直觉判断"。
- 没有 `author_experience` 要点时，全文禁止"我用了""亲测""踩坑"等亲历措辞。
- 数字、效果、收益必须有 `user_material` 来源支撑，否则删去。
- 结尾最多一个自然承接句；小红书模式末尾给 6–8 个话题标签，标签不得含夸大功效词。

## 事实门禁

- 核心要点 ≥3 条且全部标注来源等级；至少一条来自作者体验或用户素材。
- 素材链接必须全部抓取成功，失败的在创建时就会拦截。
- `must_disclose` 写明体验性表述来自作者确认、建议性内容未实测。
