## 当前运行阶段：趋势事实基座到开源趋势图文故事板

只依据分类为 `open_source_trend` 的稳定事件事实基座规划故事板。事实基座可能包含多个主体、多来源报道、时间线、变化信号、生态对比和明确未知项。

趋势图文的叙事目标不是把多个项目罗列成榜单，而是让读者按以下顺序理解趋势是否成立：

```text
观察到了什么趋势信号
  ↓
哪些主体正在推动或响应
  ↓
变化如何沿时间或生态扩散
  ↓
对比和后续观察能否支持这个判断
```

只输出严格 JSON，不输出 Markdown、发布文案、HTML、CSS 或截图指令。顶层必须直接返回 `card_plan` 数组，不要返回 `storyboard.pages` 或 `blocks` 这套内部规划结构：

```json
{
  "target_reader": "",
  "pain_point": "",
  "tool_positioning": "开源生态趋势定位",
  "must_highlight": "必须突出的一条变化信号",
  "must_disclose": "来源范围、观察窗口和不确定性",
  "getting_started": "读者理解趋势的最短路径",
  "forbidden_claims": "不得越过证据边界的判断",
  "recommended_pages": 4,
  "card_plan": [
    {
      "kind": "cover|trend|actors|timeline|positions|boundary|ending",
      "role": "cover|concept|feature|timeline|data|compare|risk|ending",
      "title": "8–14 字的页面标题",
      "goal": "本页唯一要完成的事实或判断",
      "evidence": ["事实基座中直接支持本页的证据"],
      "content_blocks": [
        {
          "type": "text|list|note|timeline|compare",
          "title": "可选小标题",
          "content": "仅 text/note 使用；内容具体、可核验",
          "items": [],
          "headers": [],
          "rows": [],
          "source_refs": ["事实基座中的来源标识"]
        }
      ]
    }
  ]
}
```

### 视觉意图示例

视觉意图只突出跨来源、跨主体或跨时间事实中的变化信号，不把单个榜单、一次发布或主观推测包装成趋势：

```json
{
  "type": "highlight",
  "title": "变化信号",
  "content": "主体 A 已公开采用路径，主体 B 仍处于测试阶段。",
  "content_runs": [
    {"text": "主体 A 已公开采用路径", "role": "metric", "tone": "accent", "emphasis": "strong"},
    {"text": "，", "role": "normal"},
    {"text": "主体 B 仍处于测试阶段", "role": "warning", "tone": "warning", "emphasis": "strong"},
    {"text": "。", "role": "normal"}
  ],
  "visual": {"icon": "timeline", "badge": "趋势证据"},
  "source_refs": ["来源1", "来源2"]
}
```

## 一、页面结构

### 1. 封面：提出趋势信号

- `kind: cover`、`role: cover`。
- 只呈现有来源、主体和观察窗口支持的变化信号。
- 不把单个仓库发布、Star 数或榜单排名直接写成行业趋势。
- 最多 1 个核心内容块，不在封面堆叠主体、时间线和待观察项。

### 2. 趋势判断：说明变化是什么

- `kind: trend`、`role: concept`。
- 先给出可检验的趋势判断，再列出支持该判断的来源和观察窗口。
- 趋势判断必须能回指多个来源、主体或时间节点；没有变化信号时改为单事件或进入候补。
- 不把“大家都在关注”“项目很多”当作趋势证据。

### 3. 推动主体：说明谁在响应

- `kind: actors`、`role: feature`。
- 列出参与主体、项目、组织或上下游角色，以及它们做了什么可核验的动作。
- 主体清单与变化路径相邻时优先合并，不为每个主体单独生成页面。
- 不推断主体动机、市场份额或行业地位。

主体动作使用列表块时，输出结构参考：

```json
{
  "type": "list",
  "title": "主体动作",
  "items": ["主体 A：发布具体方案", "主体 B：跟进具体动作"],
  "source_refs": ["来源1", "来源2"]
}
```

### 4. 时间/生态信号：说明变化路径

- `kind: timeline`、`role: timeline`。
- 至少两个有意义的时间节点或阶段变化时才单独成页；单一节点并入趋势判断或主体页。
- 时间线只记录变化，不重复主体介绍或趋势结论。
- 如果没有时间线但有跨主体信号，可以使用 `list` 说明变化信号，不编造趋势曲线。

时间线块示例：

```json
{
  "type": "timeline",
  "title": "变化路径",
  "items": [
    {"time": "2024年", "title": "主体 A 发布方案", "content": "具体变化", "source_refs": ["来源1"]},
    {"time": "2025年", "title": "主体 B 跟进", "content": "具体变化", "source_refs": ["来源2"]}
  ],
  "source_refs": ["来源1", "来源2"]
}
```

### 5. 生态对比：检查趋势是否有参照

- `kind: positions`、`role: compare` 或 `role: data`。
- 对比主体、方案、采用路径或生态位置，必须保留比较维度和来源。
- 没有可比较数据时使用主体/事件差异，不制造百分比、排名或市场规模。
- 对比和待观察项相邻时优先合并。

生态对比块示例：

```json
{
  "type": "compare",
  "title": "采用路径对比",
  "headers": ["主体", "动作", "证据"],
  "rows": [
    ["主体 A", "动作描述", "来源1"],
    ["主体 B", "动作描述", "来源2"]
  ],
  "source_refs": ["来源1", "来源2"]
}
```

### 6. 待观察：说明判断边界

- `kind: boundary`、`role: risk`。
- 写清楚趋势判断还缺什么证据、哪些信号会改变判断，以及需要继续观察的动作。
- 边界应是具体问题，而不是“仅供参考”“一切以官方为准”等泛化免责声明。
- 不因为标题含“增长”“性能”或“变化”就覆盖已给出的 `risk` 角色。

### 7. 结尾：给出后续观察

- `kind: ending`、`role: ending`。
- 总结当前可以确认的最短判断，并列出后续来源、版本、采用或生态信号。
- 不新增事实，不使用传播口号替代趋势结论。
- 最多 2 个内容块。

## 二、页面选择规则

趋势图文优先控制在 4–6 页，不机械生成全部职责页：

| 页面 | 是否默认生成 | 触发条件 |
|---|---:|---|
| 封面 | 是 | 所有合格趋势事件 |
| 趋势判断 | 是 | 至少有一个可验证变化信号 |
| 推动主体 | 条件生成 | 有两个或以上可核验主体/动作 |
| 时间/生态信号 | 条件生成 | 至少两个时间节点或阶段变化 |
| 生态对比 | 条件生成 | 有主体、方案或路径参照 |
| 待观察 | 是 | 所有趋势判断 |
| 结尾 | 是 | 所有趋势事件 |

优先采用以下紧凑结构之一：

```text
封面 → 趋势/主体 → 对比/待观察 → 结尾
封面 → 趋势/时间线 → 对比/待观察 → 结尾
封面 → 趋势/主体 → 时间/对比 → 待观察 → 结尾
```

相邻职责可以同页，但必须使用不同内容块表达不同职责。只有合并后会超出模板容量、混淆事实边界或造成结构不可读时，才保留独立页面。

## 三、事实分配与防重复

生成前建立内部事实分配表：

```text
fact_id / 事实摘要 / 主页面 / 来源引用 / 主体 / 时间节点 / 是否已经作为趋势证据使用
```

分配规则：

```text
变化判断 → 趋势判断页
主体动作 → 推动主体页
时间和阶段变化 → 时间/生态信号页
主体、方案和路径差异 → 生态对比页
证据缺口和反例 → 待观察页
后续验证动作 → 结尾页
```

同一事实只能有一个页面承担完整叙述。其他页面可以复用来源编号，但不要复制完整事实句或重复时间节点。

## 四、内容块与来源规则

- `text`：单一趋势结论、事实摘要或边界说明。
- `list`：多个主体、变化信号或观察项；必须使用 `items` 字符串数组。
- `timeline`：至少两个带时间的结构化节点；每个节点必须有来源。
- `compare`：有明确维度的主体/方案对比，必须使用 `headers` 和 `rows`。
- `note`：短事实边界、来源缺口或待观察问题。
- 每个内容块必须提供 `source_refs`；来源只能来自事实基座。
- `list` 必须使用 `items` 字符串数组，禁止在列表块写 `content` 数组或把多条事实拼成单个段落。
- 公众号渠道使用运行时允许的结构化块；不支持的块改用带来源的 `list` 或 `text`，不得改变事实含义。

## 五、趋势边界与密度

- 至少具备跨来源、跨主体或跨时间的变化信号，才能输出趋势判断。
- 单一仓库介绍、单次发布、Star/Trending 排名不能单独支撑行业趋势。
- 不虚构增长曲线、市场份额、采用率、成本收益或主体动机。
- 普通内容页通常使用 1–3 个有实质内容的块；封面最多 1 个，结尾最多 2 个。
- 时间节点、主体和观察项必须逐条保留；相关列表在容量允许时合并，不删除事实。
- 如果事实不足以支撑目标密度，保留必要留白或降级为单事件，不用重复内容填满画布。
- 模板容量、页面绝对上限和后续重排由程序门禁负责，故事板不得静默删除事实。

## 六、合并与禁止合并规则

允许合并：

- 趋势判断 + 推动主体：趋势主张与主体动作必须使用不同内容块；
- 主体 + 时间/生态信号：主体动作和时间变化相邻时可以合并，但不得重复主体介绍；
- 对比 + 待观察：比较结论与会改变判断的信号可以同页；
- 待观察 + 结尾：必须分别保留判断边界和后续观察动作。

禁止合并：

- 封面 + 普通内容页；
- 单个项目介绍 + 趋势判断；
- 不同观察窗口或不同主体集合；
- 趋势证据 + 没有来源支持的增长、采用率或市场份额推断。

合并后必须保留全部 `source_refs`、`fact_ids`、主体和时间节点，并重新检查趋势信号是否仍可独立回溯。

## 七、证据门槛、降级与常见错误

- 趋势判断至少满足跨来源、跨主体、跨时间中的两类变化信号，并写明观察窗口。
- 只有单个仓库、单次发布、Star/Trending 排名或项目数量时，降级为普通事件或开源技术/工具图文。
- 没有可比较数据时不得制造百分比、曲线、排名或市场规模；可以使用有来源的主体/事件差异。
- 不把多个项目的功能清单拼成趋势，不把主体动机或行业地位写成事实。
- 趋势证据不足时缩短为 4 页或进入候补，不能用泛化的“行业正在加速”填充。
