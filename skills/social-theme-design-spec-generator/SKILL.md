# Social 主题设计规范生成

根据主题 JSON 和已确认的视觉方向，生成一份供图文 Agent 读取的 `AI_DESIGN_SPEC.md`。这份文件描述主题如何表达视觉语言，不承载具体候选的事实、报道或故事板内容，也不定义页面模板或程序渲染结构。

## 输入

至少需要：

- 主题 `id`、`label`、`version`；
- `tokens.colors`、`tokens.typography`、`tokens.spacing`、`tokens.shape`；
- `social.recipes`、`social.effects` 和 `social.components`；
- 主题可使用的组件语义和视觉效果（若有）。

## 输出

只输出完整 Markdown 文档，不要把整份文档包在代码围栏中，也不要把候选内容输出成独立 JSON/HTML；文档内部可以用短代码片段说明 CSS/HTML 用法。文档必须包含：

1. 主题定位：适用内容、视觉气质和视觉重心；
2. 颜色、字体、间距、圆角、阴影等实际 Token；
3. 页面结构边界：说明本主题如何套用通用页面结构，以及主题页眉/组件类名如何接入；不重复定义完整 HTML 骨架；
4. 主题前缀如何覆盖通用组件的视觉属性；
5. 主题组件如何覆盖通用组件的颜色、字体、边框、圆角、投影和渐变；
6. 主题视觉在通用组件中的适用边界；页面角色、内容层组合和页面编排由视觉契约与生成技能定义；
7. 主题组件与通用版式规范的边界说明；
8. 一个最小可实现示例。
9. 必须落地的装饰层：根据 `social.recipes.decoration` 和 `social.effects` 给出可执行的装饰线、渐变、纹理、圆弧或错位层；不能只描述“可添加装饰”。

## 规则

- 所有颜色、字号、间距、类名和主题 ID 必须来自输入，不能臆造与主题冲突的 Token。
- 同时给出实际颜色值和运行时变量映射：`var(--bg)`、`var(--page)`、`var(--surface)`、`var(--ink)`、`var(--muted)`、`var(--accent)`、`var(--accent2)`、`var(--line)`、`var(--inverse)`、`var(--code)`。
- 主题专属类名必须使用输入主题对应的前缀；不要把某一主题的 `ic-*` 类名复制给其他主题。
- 设计规范可以提供 CSS 配方和 HTML 片段，但不得包含候选事实、来源 URL、内部 ID、事件数字或仓库信息。
- 主题组件必须能在通用版式约束下使用；正文和辅助文字的最小字号、间距、利用率、溢出及裁切门禁以 `layout-guide.md` 和 AI 视觉技能为准，不在主题规范中另设一套数值。
- 规范应允许 AI 自由组合卡片，不要把每一页固定成同一种卡片；但要明确哪些组件适合当前主题，以及何时使用指标、对比、箭头、徽章和提示卡。
- 主题应说明如何用自己的 `accent / accent2 / surface / inverse` 区分强、中、弱三档信息层级，并分别支持数字焦点、证据边框卡和结论色块；这里只定义视觉映射，不规定页面必须出现何种角色或组件。
- 主题组件必须给出可执行的“强视觉层”做法：至少通过本主题的边框、圆角、投影、渐变或强调色建立层级，不得只写“必要时”。具体字号、通用组件数量、布局值和组件结构以 `layout-guide.md` 与视觉契约为准，不强制所有主题使用同一套边框、数字字号、列表前缀或箭头写法。投影写法必须按主题阴影类型适配：`hard` 用硬投影、`soft` 用柔和投影、`glow` 用霓虹光晕、`none` 用边框或色块分层。
- 装饰层必须与主题配方一致：`orbit` 至少落地细边框/轨道环之一，`soft-blur` 落地模糊渐变光斑，`scanlines` 落地重复横线，`paper-offset` 落地受控错位，`circle` 落地圆弧/圆形轮廓；`none` 才可以不生成独立伪元素。装饰必须位于内容后方、使用 `pointer-events:none`，且每页至少出现一个可见装饰元素。
- 更新已有 SPEC 时保留稳定章节和主题事实，只修正与当前主题配置不一致的内容。
