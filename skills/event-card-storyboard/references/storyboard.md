## 当前运行阶段：突发事实基座到热点事件图文故事板

只依据事件事实基座规划故事板。事实基座可能包含确认事实、带来源的未核实主张、各方回应、时间节点、来源审计和开放问题。

事件图文的叙事目标不是把素材罗列成新闻摘要或免责声明，而是让读者按以下顺序理解事件，并在事实基础上形成讨论：

```text
发生了什么
  ↓
关键变化
  ↓
为什么值得讨论 / 哪些地方仍有分歧
  ↓
接下来观察什么
```

只输出严格 JSON，不输出 Markdown、发布文案、HTML、CSS 或截图指令：

```json
{
  "target_reader": "",
  "pain_point": "",
  "tool_positioning": "热点事件内容定位",
  "must_highlight": "必须突出的一条核心事实或冲突",
  "must_disclose": "来源、未核实主张和事实边界",
  "getting_started": "读者进入事件的最短路径",
  "forbidden_claims": "不得越过证据边界的判断",
  "recommended_pages": 4,
  "card_plan": [
    {
      "kind": "cover|what-happened|timeline|positions|ending",
      "role": "cover|concept|timeline|compare|ending",
      "title": "8–14 字的页面标题",
      "goal": "本页唯一要完成的事实或判断",
      "evidence": ["来源 N 支持的内容"],
      "content_blocks": [
        {
          "type": "{{CARD_BLOCK_TYPES}}",
          "title": "可选小标题",
          "content": "具体、可核验的内容",
          "items": [],
          "source_refs": ["事实基座中的来源标识"]
        }
      ]
    }
  ]
}
```

## 一、页面结构

### 1. 封面：一句话说明事件

- `kind: cover`、`role: cover`。
- 只呈现已经有证据支持的核心事件或核心冲突。
- 标题可以保留完整主张，但必须标记“据称”“拟”“回应称”等不确定性。
- 不在封面堆来源、背景、影响和风险。
- 最多 1 个核心内容块，通常只用于补充时间或来源边界。

### 2. 发生了什么：建立共同事实

- `kind: what-happened`、`role: concept`。
- 回答谁、在什么时候、做了什么、目前确认到什么程度。
- 这是事件的主事实页面，核心事实优先放在这里，不要在后续页面重复改写。
- 适合使用 1 个事实摘要块加 1 个边界/状态块。
- 不把尚未证实的推测写成事件结果。

### 3. 时间线：只讲时间变化

- `kind: timeline`、`role: timeline`。
- 只有在事实基座至少有两个有意义且顺序不同的时间节点时才单独成页；如果与主事实页合并后仍符合模板容量，则优先合并。
- 每个时间节点只出现一次，按时间顺序排列；节点内容应说明“发生了什么变化”，不能只是重复当前事件摘要。
- `关键节点`、`事件进展`、`阶段变化`只能选择一个作为主时间线标题，不得并列生成两组相同节点。
- 如果只有一个时间点，不生成时间线页；将时间信息放入“发生了什么”或“当前状态”。
- 小红书可使用 `timeline.items`：

```json
{
  "type": "timeline",
  "title": "事件时间线",
  "items": [
    {"time": "2019年", "title": "港股上市", "content": "具体事实", "source_refs": ["来源1"]},
    {"time": "2025年", "title": "宣布配售", "content": "具体事实", "source_refs": ["来源2"]}
  ]
}
```

- 公众号渠道当前允许的结构化块较少时，使用 `type: list`，每一条仍然按时间顺序写入 `items`，不要把多个节点拼成逗号连接的一段话。
- 不要为了填充画布，把“阶段变化”再作为第二个列表块重复核心时间线。

### 4. 争议与讨论：把事实转成可讨论的问题

- `kind: positions`、`role: compare`；这是事件图文的默认讨论承载页，不要求一定存在多方回应。
- 有多方回应时，分别陈述“谁说了什么”；没有多方回应时，围绕事实支持的影响、分歧或未知信息提出 1–3 个具体讨论点。
- 来源核验、未核实状态、时间缺失和事实边界作为本页的 `note`、`list` 或 `compare` 内容块出现，不单独生成“信息来源与核验”页或“事实边界和开放问题”页。
- 讨论点必须能回指事实或来源，使用“哪些信息还缺”“什么变化会改变判断”“谁会受到影响”等问题式表达；不要使用“请理性看待”“一切以官方为准”这类空泛免责声明。
- 不把媒体转述、网友评论和官方回应混为同一方，也不把可能影响写成已经发生。
- 至少一页说明事实边界，并把来源缺口、争议或开放问题转成具体讨论点。

### 5. 结尾：给出后续观察点

- `kind: ending`、`role: ending`。
- 总结当前可以确认的最短结论，并列出下一步应关注的公告、回应、数据或时间节点。
- 不新增事实，不重复整页时间线。
- 不使用“快转发”“冲上热搜”等传播诱导替代后续信息。
- 最多 2 个内容块。

## 二、页面选择规则

推荐页数为 4–10 页，但页面按事实条件选择，不机械生成全部页型：

| 页面 | 是否默认生成 | 触发条件 |
|---|---:|---|
| 封面 | 是 | 所有事件 |
| 发生了什么 | 是 | 所有事件 |
| 时间线 | 条件生成 | 至少两个有意义的时间节点 |
| 争议与讨论 | 是 | 有事实支持的分歧、影响或开放问题；来源与事实边界并入本页 |
| 结尾 | 是 | 所有事件 |

如果条件页全部触发，优先使用：

```text
封面 → 发生了什么 → 时间线 → 争议与讨论 → 结尾
```

页面不足时，优先合并同一叙事职责相近的页面：

- “发生了什么”可以和至少两个节点的时间线合并，前提是模板容量允许；
- 来源核验、事实边界和开放问题应优先并入“争议与讨论”；
- “争议与讨论”可以和“后续观察”合并，但不能因此删除具体开放问题。

不得合并：

- 不同主体的回应；
- 已确认事实和未核实主张；
- 时间线节点与讨论问题：可以同页，但必须使用不同内容块和不同叙事职责。

## 三、事实分配与防重复要求

### 3.1 主页面分配

每个核心事实只分配一个主页面：

```text
核心事件事实 → 发生了什么
时间变化事实 → 时间线
来源状态、事实边界 → 争议与讨论页内的核验/边界块
主体回应、事实分歧 → 争议与讨论
直接影响、开放问题 → 争议与讨论
后续验证动作 → 结尾
```

其他页面可以引用来源编号，但不要复制主页面的完整事实句。

### 3.2 时间线防重复

时间线页面只允许一个主时间节点列表或时间线块。以下标题不能同时出现并承载相同内容：

- 关键节点；
- 阶段变化；
- 事件进展；
- 发展过程；
- 时间线。

如果一个页面需要第二个内容块，第二个块必须承担不同职责，例如“当前状态”或“尚未披露”，并且不能重新列出同样的日期和事件。

### 3.3 跨页面防重复

生成前先在内部建立事实分配表。模型不需要输出该表，但必须按它规划：

```text
fact_id / 事实摘要 / 主页面 / 是否允许引用来源 / 是否已经作为时间线节点使用
```

同一事实可以在讨论页作为来源核验对象被提及，但只能有一个页面承担该事实的完整叙述。

### 3.4 内容块类型

- `text`：单一结论、事实摘要或边界说明；
- `list`：多个并列事实、来源或风险点；多条内容必须放入 `items`；
- `timeline`：带时间、标题和内容的多个时间节点；至少两个条目；
- `compare`：多方回应或立场差异；必须使用 `headers` 和 `rows`；
- `note`：短事实边界、核验状态或开放问题。

不要用 `content` 数组表达多条内容，不要把列表条目拼成逗号连接的单个字符串。

## 四、事实与表达边界

- 每个内容块必须提供 `source_refs`，结构化条目可以单独提供来源引用。
- 来源引用只能来自事件事实基座，不得编造来源编号、URL、时间、数字或引语。
- 未核实内容必须保留“声称”“据其发布”“尚未获独立证实”等表达。
- 多方回应必须保留主体，不得把转述变成事实。
- 禁止推断动机、违法性、责任、因果关系或群体标签。
- `goal` 只写本页内部事实目标，不写“让读者了解”“读者能够”等教学指令。
- 不输出 CSS、坐标、尺寸、本地路径或 HTML。

## 五、密度与模板边界

- 封面最多 1 个内容块；结尾最多 2 个内容块。
- 普通事件内容页通常使用 1–3 个内容块；不要为了满足数量而复制事实。
- 单页最多 2 个列表块，列表条目合计不超过 9 条。
- 时间线只有在至少两个节点成立时使用；单节点不得强行画时间线。
- 如果事实不足以支撑目标密度，保留事实边界和必要留白，不使用重复内容填充。
- 模板能力、页面绝对上限和后续重排由程序门禁负责，故事板不得为了填满画布虚构内容。
