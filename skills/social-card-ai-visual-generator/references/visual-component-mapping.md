# 视觉解释与组件映射契约

> 本文件由 `social-card-ai-visual-generator` 运行时作为内置参考注入，不复制到候选工作目录，也不属于 `workspace.files`。本文件只负责事实语义到视觉组件的映射建议。

本参考文件用于把 `card-plan.json` 的事实语义转换为视觉表达。它不改变页数、页序、标题、数字、来源或事实边界，也不规定每一页必须使用固定模板。

## 生成前的解释顺序

在写入第一段 CSS 或第一页 HTML 前，先对整组页面完成以下判断：

1. 逐页读取 `kind`、`role`、`content_blocks.type`、`visual`、`evidence`、`composition` 和正文中的事实结构。
2. 标出该页唯一的首要视觉焦点：数字、变化、流程、问题、证据、风险、结论或适用人群。
3. 为首要焦点选择一个主组件，再选择 1–2 个辅助组件；普通内容页通常形成 3–4 个有意义的视觉层。
4. 根据当前主题 SPEC 的颜色、形状、投影、纹理和装饰配方，决定组件的主题处理，不跨主题复制颜色或类名。
5. 检查相邻内容页是否重复使用相同的主轮廓、强调位置和层级组合；如果重复，改变构图节奏，但不制造无事实依据的内容。

## 整组视觉振幅基线

组件映射完成后，再检查整组而不是单页：

- 至少出现 3 种不同的语义主组件类型；
- 至少 1 页使用大数字/指标带、强调色块、终端面板或同等强度组件作为第一视觉层；
- 普通表面卡和描边卡只承担中层信息，不能成为整组页面的唯一表达；
- 相邻页面改变主组件、构图方向、强调位置或明暗层级中的至少一项；
- 每页都有主题可感知的装饰或质感层，且原尺寸可见。

这些是视觉振幅的最低基线，不是固定模板。若事实不支持某类组件，选择语义匹配的替代组件，不得虚构内容来凑数量。

## 语义到组件的默认映射

这些是可供 Agent 自由组合的候选，不是固定模板：

| 输入语义 | 优先组件 | 视觉目的 |
|---|---|---|
| 数字、比例、价格、规模、版本 | `metric-focus` / `metric-band` | 让独立事实成为最大焦点 |
| 步骤、流程、执行循环、时间顺序 | `process-rail` / `step-stack` / `timeline` | 表达顺序、节点和动作关系 |
| 3–4 个并列问题、能力或选项 | `signal-grid` / `feature-grid` / `comparison-row` | 建立横向对比和扫描节奏 |
| 风险、限制、未验证项、证据边界 | `warning-panel` / `evidence-frame` | 提高边界信息的辨识度 |
| 代码、命令、安装指令 | `terminal-panel` / `code-block` | 保留命令的操作属性和可复制性 |
| 结论、总结、适合人群、下一步 | `accent-fill` / `conclusion-card` / `checklist` | 形成明确收束和行动提示 |
| 人物、组织、产品或平台 | `entity-badge` / `entity-row` | 突出名称但不虚构图标或资料 |
| 普通解释文字 | `text-block` / `surface-card` | 承接信息，不抢主焦点 |

选择组件时优先看事实结构，不要只看故事板里的 `visual` 标记；`visual` 是提示，不是要求 Agent 机械复用。

## 视觉计划格式

Agent 可以在内部按以下结构完成计划。若编排器提供中间工作文件，也可以写入 `ai-visual-design-plan.json` 供后续阶段读取；该文件不是页面正文和最终交付素材。

```json
{
  "pages": [
    {
      "page": 3,
      "primaryFocus": "执行循环",
      "visualReason": "页面包含连续动作和多步骤机制",
      "primaryComponent": "process-rail",
      "secondaryComponents": ["architecture-strip", "entity-badge", "evidence-frame"],
      "themeTreatment": {
        "strong": "主题强调色边框或色块",
        "medium": "主题表面卡",
        "weak": "辅助文字和细分隔线",
        "decoration": "按主题配方落地并在原尺寸可辨认"
      }
    }
  ]
}
```

## 创作自由与不可改变项

Agent 可以自行决定：

- 主组件横向、纵向、分栏或错位的构图；
- 强调色放在数字、边缘、标题、节点或底部；
- 同一语义组件在当前主题下的边框、色块、渐变、投影和装饰位置；
- 相邻页面如何改变组件尺寸、明暗层级或强调位置。

Agent 不可以自行决定：

- 新增或删除页面、改变页序；
- 修改独立数字、比例、价格、产品名、平台名、限制条件或因果关系；
- 为了填充空间虚构指标、步骤、人物、图标含义或结论；
- 把主题装饰降级为仅存在于 CSS、原尺寸不可辨认的弱透明层；
- 用同一种普通圆角表面卡片覆盖整组页面。

## 实现前检查

在第一次页面写入前，Agent 应确认：

- 当前主题至少有两档强弱视觉层级；
- 当前组页面至少使用三种主组件类型，并至少有一页承担强视觉焦点；
- 每个普通内容页都有一个首要视觉焦点；
- 主题装饰会落到 `.page::before`、`.page::after` 或页面背景；
- 页面中出现的组件类名都已有实际 CSS 选择器。
