## 当前运行阶段：README 到工具图文故事板

只依据已核验仓库事实和 README 生成图文决策，不得虚构体验、效果、性能、价格、权限或数字。故事板必须让读者明确回答：它是什么、解决什么具体问题、核心功能如何工作、怎样开始、适合谁、有什么限制。禁止用 GitHub topics 代替功能解释。

先从具体读者任务出发：`target_reader` 写明角色与使用场景，`pain_point` 写明正在完成的任务及当前阻碍或成本，`tool_positioning` 说明工具在该任务中的作用。Star、Trending 和项目知名度只作为证据，不作为读者价值本身。封面主标题优先使用“具体任务或问题 + 结果方向”，陌生项目名作为辅助信息。

规划前必须先判断仓库原型，再选择故事线，禁止所有仓库机械套用“痛点 → 能力 → 安装 → 场景 → 总结”：

- `awesome/list/catalog`：README 以大量分类链接、资源条目或项目索引为主体。故事线优先为“这份清单覆盖什么 → 如何选/如何逛 → 代表性分类与具体条目 → 收录标准/更新机制 → 安全或质量边界”。只有仓库本身提供可运行程序时才安排安装页；不得把“安装列表中的某个项目”写成“安装这个列表”。
- `library/sdk/framework`：优先为“开发任务 → 核心抽象/API → 最小代码路径 → 与替代方案的取舍 → 兼容性和维护边界”。
- `cli/app/extension/service`：优先为“使用场景 → 工作机制/能力 → 完整上手路径 → 关键设置或实际工作流 → 权限与限制”。
- `template/boilerplate`：优先为“产出物 → 目录与约定 → 从复制到首次运行 → 可定制点 → 适用边界”。
- `dataset/benchmark`：优先为“数据覆盖 → 字段/规模/来源 → 获取与使用 → 可做的分析 → 许可、偏差与更新边界”。

若同时符合多类，选择 README 主体占比最高、最能解释读者价值的一类。每页标题与内容必须体现该原型；页面 `kind` 仍使用允许枚举，但不等于固定页序。

补充要求：

- 内容页和结尾页标题只保留核心主题或结论，禁止使用“标题：解释句/操作说明”的结构；解释放入 `content_blocks`，封面标题可保留完整主张；

- 每页内容块遵守固定画布密度预算：封面最多 1 个、内容页 2–3 个、结尾页最多 2 个；同一页最多 2 个列表块，单页列表条目合计不超过 9 条。超出推荐页数时不得裁剪事实，生成阶段会优先合并或拆分续页；只有超过绝对安全上限才阻断。能力页必须写出 README 中的具体能力和工作方式，快速上手页保留真实命令，限制页明确未核验项。
- `list` 内容必须逐条写入 `items`，禁止使用列表块的 `content` 承载多条事实；列表项可以是字符串，不能把多个条目拼成一段话。
- must_disclose 必须说明“基于项目文档整理，未实际运行”以及未知权限、网络和成熟度。
- 推荐用 4～7 页；内容适合时优先用 5～6 页组织为封面、痛点、能力、可选能力或场景、快速开始、结尾，不为凑页重复内容。内容确实较多时允许生成续页，不能为回到推荐页数删除事实。
- 相邻职责可以在模板容量允许时合并：痛点与核心能力、核心能力与快速上手、限制与结尾分别可以合并为一页；合并后必须保留两个职责对应的完整内容块。快速上手与结尾、不同具体场景、封面与内容页不得合并。
- 不单设信息贫乏的“适用场景”页：如果只有 2～3 条泛化人群标签，把它们并入结尾或限制页；独立场景页至少包含两个具体场景及各自的“触发条件/用法/边界”，或再配一个事实支持的决策、配置、示例块。列表型仓库优先把页面预算留给具体分类、代表性条目和选用路径。
- README、仓库元数据、LICENSE 和 Release 只能表述为“项目文档显示”或“项目提供”；只有输入中存在明确运行记录时，才能写“实测”“跑通”和具体耗时。无法核验的权限、网络、成熟度、兼容性或性能直接标记未知。
- 保留 README 中真实存在的命令和用户参数。`<commit>`、`YOUR_TOKEN`、`$API_KEY` 等参数须说明替换位置和用途，优先改写为 `$COMMIT_SHA` 等语义清晰的变量名；含用户参数时不得宣称“复制即用”或“无需配置”。README 未提供完整命令时写操作说明，不补造命令。
- 每个内容块必须提供 `source_refs`，结构化条目可单独提供 `source_refs`；引用应对应事实基座中的 README 章节、仓库事实或已核验素材，不得创建虚构来源。
- 结尾优先说明适合哪些角色和场景、不适合哪些约束，以及使用前需要确认的权限、网络、版本、成本或安全事项；不用“点赞、收藏、转发”代替内容结论。
