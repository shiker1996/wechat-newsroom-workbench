# 公众号文章封面视觉契约

> 本文件由 `article-cover-ai-visual-generator` 运行时作为内置参考注入，不复制到候选工作目录，也不属于 `workspace.files`。这是生成指导，不是运行时 HTML 门禁。

## 1. 适用边界

封面是单页横向视觉作品。Agent 负责完整 HTML、CSS、文字层、主题表达和装饰；程序只负责保存原始 HTML、截图和检查最终图片是否交付成功。

契约不要求固定插槽、不要求程序补写内容、不要求浏览器布局审计，也不恢复 HTML 结构或布局门禁。它只约束视觉设计决策和输入事实边界。

## 2. 推荐语义结构

类名可以由主题自行命名，但页面应能辨认以下职责：

```html
<main class="page">
  <div class="cover-primary"><!-- 标题、摘要、主信息 --></div>
  <div class="cover-visual"><!-- 足够面积的主题主视觉 --></div>
  <div class="cover-meta"><!-- 品牌、日期、短标签 --></div>
</main>
```

这是语义参考，不是必须照抄的 DOM 模板。也可以用一个主题化版心、分栏、斜切层、边框系统或全幅背景表达同样的职责。

## 3. 最低视觉关系

- 每张封面只有一个首要焦点：标题或主题主视觉；
- 必须有一个可辨认的第二视觉层，不能只输出标题和空背景；
- 文字与视觉表达应形成可解释的整体关系；若采用分区构图，各分区都应服务于主题，不要求采用左文右图；
- 至少形成强、中、弱三档层级：标题/主视觉，摘要/辅助图形，品牌/日期/标签；
- 这些层级是视觉质量目标，不要求固定 DOM、固定位置或固定组件；
- 装饰应服务于主题和层级，不能遮挡文字，也不能成为唯一的视觉内容；
- 任何主题图形都不能为了填充空间而虚构具体数据、人物、产品功能或事实结论。

## 4. 文字真实性

只允许使用 `cover-visual-input.json` 中提供的标题、摘要、品牌和日期信息。标题可以换行、分组和改变字重，但不得改写事实、擅自补充内容或把日期解释成期号。

禁止自行创造以下信息：

- `NO.026`、Issue、Vol.、第 X 期等期号；
- 文章编号、栏目号、排名、百分比、版本号或统计数字；
- 输入中没有提供的作者、媒体、组织、产品数据或时间；
- 看似真实但没有输入依据的标签和结论。

如果没有明确提供栏目标签，就不要为了获得杂志感而补一个栏目标签。日期只能按输入提供的日期原样或安全缩短展示，不能据此推断文章顺序。

## 5. 创作自由

Agent 可以自由决定构图方向、CSS 类名、色块位置、图形表达、字体层级、边框、投影、渐变、内联 SVG 和装饰比例。`visualMetaphorCandidates` 只是可选灵感，`primaryFocus` 只是内容焦点；都不要求被逐项采用。空间安全区和可读性参考 `cover-layout-guide.md`，主题语言服从当前主题 SPEC。
