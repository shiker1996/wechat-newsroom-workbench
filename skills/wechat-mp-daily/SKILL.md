# 公众号批次早报

使用上游提供的 `focus` 与 `news_items` 写一篇可快速扫读的主题早报。`focus` 可以包含多个主体、动作或场合关系；先找出它们的共同信息主线，再组织正文。不得使用模型常识补充事实。

## 输入契约

`focus` 包含 `dimension`（`who|what|where`）、`key` 与面向读者的 `label`。每条 `news_item` 至少包含：

- `event_id`
- `title`
- `conclusion`
- `key_facts`
- `uncertainties`
- `sources`：标题、媒体名、URL、时间

只采用有来源直接支持的事实。`uncertainties` 只能作为明确标注的待核实信息，默认不写入正文。

## 输出结构

- 只输出 Markdown 完整文章。
- 使用唯一一个 H1 标题。
- 标题和导语必须兑现选定的主体、动作或场合视角，不写成泛化的“今日新闻”。
- 导语控制在 60–100 字，先说明这一维度下出现了什么共同信号。
- 将关联事件去重后归纳为 2–6 个信息段落；相近事件可以合并，不能为凑段落逐事件罗列。
- 每段使用 H2；首句直接给该段结论，随后保留关键事实、事件间关系、读者影响和来源链接。
- 主体维度按主体近期动作及其变化组织；动作维度比较不同主体的同类动作；场合维度总结同一场合释放的集中信号。
- 结尾用 1–2 句给出有条件的趋势判断，并附一个与当日主题具体相关、可作答的留言引导问题；禁止“你怎么看”“欢迎留言”式泛问。
- 正文可见字符控制在 1300–1800 字，硬上限 1800 字。

## 写作门禁

- 不写来源没有支持的数字、时间、人物动作、排名、引语或因果结论。
- 不把事件卡的推断、风险和不确定信息改写成确定事实。
- 不在正文暴露内部 `event_id`，不要求每个事件独立成段或独立引用；合并归纳时确保关键事实有可追溯来源。
- 不写“据爆料”“有消息称”等模糊来源；直接链接实际来源。
- 不虚构作者亲测、内部消息或读者反馈。
- 裁员、事故、医疗、违法和诉讼等严肃事件保持中性，不使用调侃语气。
- 若不足 2 条可核验的关联事件，停止并返回缺口，不凑数。

## 自检

交付前确认：文章始终围绕 `focus`；覆盖全部重要关联事件；段落为 2–6 个；每段首句是结论并含来源链接；所有数字与具体断言均能在输入中定位；全文不超过 1800 个可见字符。
