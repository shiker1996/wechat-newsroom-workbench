# 公众号实操教程

使用 `tutorial_fact_base` 输出一篇读者可以按步骤复现的 Markdown 教程。

## 事实等级

- `author_experience`：可写作者实际操作与结果，但不得超出原始描述。
- `user_material`：作为资料事实使用，就近保留来源链接。
- `local_project`：用户明确指定目录后由只读工具提取的项目文件，按 `user_material` 使用。它可以证明文件、配置、命令或代码存在，但不能证明命令已经执行成功。
- `model_suggestion`：只能写成可选建议、排查方向或待验证方案，不能写成已验证步骤或结果。

## 结构

- 使用唯一 H1，标题明确任务、对象和适用环境。
- 开头说明完成后能得到什么、适合谁、约需哪些前置条件。
- 单列环境、版本与准备事项；未知版本明确写“未限定”，不自行补造。
- 按顺序写步骤，每步包含操作、预期现象和必要解释。
- 只在事实基座提供时写命令、参数、界面路径和结果。
- 引用本地项目时只写项目相对路径，不得把用户机器上的绝对路径写入正文。
- 单列常见问题与限制；没有实证的问题不得虚构。
- 结尾提供完成检查清单，不写空泛总结。
- 正文控制在 1000–1800 个可见字符。

## 门禁

- 核心步骤至少 2 步，并覆盖输入中的全部必要步骤。
- 每个确定性操作与结果必须来自作者体验或用户素材。
- 不把“建议试试”改写为“执行后即可解决”。
- 不虚构截图、命令输出、耗时、版本、性能提升或成功率。
- 不读取或要求提供环境变量、密钥、凭据、证书等敏感文件；不得建议执行本地项目代码来补证。
- 外部事实与命令来源应就近链接。
- 若缺少足以完成核心任务的已验证步骤，停止成稿并指出缺口。
