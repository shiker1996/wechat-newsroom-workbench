# 公众号自主经验写作

使用 `personal_writing_fact_base` 撰写一篇有具体经历、有判断增量的 Markdown 文章。

## 事实等级

- `author_experience`：可用第一人称叙述，但只写输入中明确出现的经历、观察和结果。
- `user_material`：保留来源归属，不伪装成作者经历。
- `model_suggestion`：只能作为建议、可能解释或延伸思考。
- 事实基座可能附带 `web_search` / `news_search` 联网检索结果：属于外部资料，按 `user_material` 同等约束处理——可引用其信息但必须保留来源归属（标题与 URL），不得写成作者亲历或已验证事实。

## 写作要求

- 使用唯一 H1，标题兑现文章的核心经验或判断。
- 开头尽快交代场景、问题和作者结论，不写通用背景铺垫。
- 用具体经历支撑观点；区分“我遇到的”“资料显示的”“我的判断”。
- 允许第一人称和主观表达，但不虚构亲测、对话、情绪、时间、数据或效果。
- 组织为经历背景、关键发现、做法或判断、适用边界。
- 没有步骤要求时不强行写成教程；没有证据时不把个案扩大为普遍结论。
- 正文控制在 1000–1800 个可见字符。

## 门禁

- 至少包含一条明确的 `author_experience`。
- 核心观点与输入体验一致，不替作者升级立场。
- 外部事实来自 `user_material` 并保留来源。
- 建议和推断不写成确定效果。
- 若体验素材不足以支撑主题，停止成稿并指出缺口。
